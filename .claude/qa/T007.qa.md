## Manual QA — T007

**Prerequisites:** Docker Desktop running. Repo root `.env` exists (copied from root `.env.example`) with `SA_PASSWORD` set. All commands below must be run from the **repo root** with no `-f` flags — the root `.env` sets `COMPOSE_FILE` to merge `src/infra/docker-compose.yml` + `src/infra/docker-compose.override.yml` automatically. Passing `-f` explicitly changes Compose's project directory to `src/infra/`, where there is no `.env`, causing `SA_PASSWORD must be set` errors even when the root `.env` is correctly filled in. No `mongodb-data` volume from a prior run if you want to exercise first-boot init (see step 1).

1. From the repo root, ensure a clean slate for Mongo only:
   `docker compose down -v --remove-orphans`
   Expect: containers removed, including the `mongodb-data` volume (so init scripts will run fresh).

2. Start just Mongo:
   `docker compose up -d mongodb`
   Expect: `mongodb` container starts; `docker compose ps mongodb` eventually shows `STATUS` as `Up (healthy)` within ~15-25s (healthcheck `start_period: 15s`, `retries: 10`).

3. Check the init scripts actually ran:
   PowerShell: `docker logs mongodb 2>$null | Select-String "mongo-init"`
   (bash/Git Bash: `docker logs mongodb 2>&1 | grep "mongo-init"`)
   Expect two lines:
   `[mongo-init] ChatServiceDb ready — messages (TTL 7200s), chat_rooms initialized.`
   `[mongo-init] ReportServiceDb ready — reports collection initialized.`
   Failure looks like: no such lines present, or a stack trace mentioning `NamespaceExists` or `IndexOptionsConflict`.

4. Verify the TTL index exists with the right `expireAfterSeconds`:
   `docker exec -it mongodb mongosh --quiet --eval "JSON.stringify(db.getSiblingDB('ChatServiceDb').messages.getIndexes())"`
   Expect: output includes an entry with `"key":{"sent_at":1}` and `"expireAfterSeconds":7200`.

5. Verify the two single-field query indexes on `messages`:
   `docker exec -it mongodb mongosh --quiet --eval "JSON.stringify(db.getSiblingDB('ChatServiceDb').messages.getIndexes())"`
   Expect: entries for `{"chat_id":1}` and `{"sender_id":1}` in addition to the TTL index and the default `_id_` index (4 total).

6. Verify `chat_rooms` index:
   `docker exec -it mongodb mongosh --quiet --eval "JSON.stringify(db.getSiblingDB('ChatServiceDb').chat_rooms.getIndexes())"`
   Expect: entry for `{"connection_id":1}` plus `_id_` (2 total).

7. Verify `ReportServiceDb.reports` indexes:
   `docker exec -it mongodb mongosh --quiet --eval "JSON.stringify(db.getSiblingDB('ReportServiceDb').reports.getIndexes())"`
   Expect: entries for `{"reported_id":1}` and `{"filed_at":1}` plus `_id_` (3 total).

8. Confirm TTL actually deletes data (functional, not just structural, check). Tear down and restart with a short TTL:
   `docker compose down -v`
   PowerShell: `$env:MONGO_TTL_SECONDS=30; docker compose up -d mongodb`
   (bash/Git Bash: `MONGO_TTL_SECONDS=30 docker compose up -d mongodb`)
   Wait for healthy, then insert a test document:
   `docker exec -it mongodb mongosh --quiet --eval "db.getSiblingDB('ChatServiceDb').messages.insertOne({chat_id:'test',sender_id:'u1',content:'hi',sent_at:new Date()})"`
   Expect: `{ acknowledged: true, insertedId: ObjectId('...') }`

9. Confirm the index picked up the overridden 30s TTL:
   `docker exec -it mongodb mongosh --quiet --eval "JSON.stringify(db.getSiblingDB('ChatServiceDb').messages.getIndexes())"`
   Expect: `"expireAfterSeconds":30` on the `sent_at` index (proves `ensureTtlIndex`'s drop-and-recreate path fired against the pre-existing 7200 index from a prior run, if the volume wasn't wiped, or confirms fresh creation at 30 if it was).

10. Wait ~90 seconds (MongoDB's TTL background monitor sweeps roughly every 60s, so allow one full cycle plus margin), then re-check:
    `docker exec -it mongodb mongosh --quiet --eval "db.getSiblingDB('ChatServiceDb').messages.countDocuments({})"`
    Expect: `0` — the test document is gone. Failure looks like: the document is still present after 90+ seconds, indicating the TTL index isn't actually enforcing expiry.

**Cleanup:** `docker compose down -v` (from the repo root) to remove the test containers and volume, then unset any one-off `MONGO_TTL_SECONDS` shell override before resuming normal work.
