## Manual QA — T010

**Prerequisites:** Windows 11, non-admin PowerShell prompt, network access. Ideally test on a machine that has (or can be given, e.g. via an old Oracle JDK MSI) a machine-level `javapath` PATH entry, to exercise the shadowing branch.

1. Open a fresh, non-admin PowerShell window and run:
   `powershell -ExecutionPolicy Bypass -File .\dev-setup.ps1`
   Expect: script runs to completion without any admin/elevation prompt; ends with a summary table and either "All tools ready" or a warning count line.

2. Check the summary table's `JDK 21 (Temurin)` row on this first run.
   Expect: `Installed` (or `AlreadyPresent` if Temurin 21 was already Scoop-installed previously).

3. Open a **brand-new** terminal window (not the one the script ran in) and run:
   `java -version`
   Expect either:
   - Output containing `"21"` or `"21.0.x"` → PATH is clean, no shadowing. Continue to step 5.
   - A non-21 version → this is the known PATH-precedence case. Continue to step 4.

4. (Only if step 3 showed non-21) Confirm the script warned you about this. Scroll back through the script's own console output for the line printed during the run (dev-setup.ps1:170 or :200) — it should read approximately:
   `Note: 'java' on PATH doesn't resolve to version 21 (...). A machine-level Java install (e.g. Oracle's 'javapath' entry) likely wins PATH precedence over Scoop's user-level shim. Work around it by setting a user-scoped JAVA_HOME pointing at the Temurin 21 install under scoop\apps\temurin21-jdk\current, or by prepending Scoop's shim directory to PATH in your PowerShell profile ($PROFILE).`
   Then verify the workaround itself works — run:
   `& "$env:USERPROFILE\scoop\apps\temurin21-jdk\current\bin\java.exe" -version`
   Expect: this direct path shows version 21, proving Scoop's install is correct even though `java` on PATH is shadowed. **Do not treat the plain `java -version` mismatch as a script failure** — it's an environment condition outside the script's control (no-admin constraint), which it now correctly detects and explains.

5. Re-run the exact same command from step 1 a **second time**:
   `powershell -ExecutionPolicy Bypass -File .\dev-setup.ps1`
   Expect: `Scoop` row shows `AlreadyPresent`; both `Scoop bucket: java` and `Scoop bucket: extras` rows show `AlreadyPresent`; **the `JDK 21 (Temurin)` row shows `AlreadyPresent`, not `Installed`** — this is the exact behavior that was broken in cycle 1 and fixed in this pass. `IntelliJ IDEA CE` row also shows `AlreadyPresent`.

6. Confirm no reinstall network activity happened on the second run — the run should complete noticeably faster than the first run and produce no "Installing ... via Scoop" lines for Scoop, the buckets, JDK 21, or IntelliJ.

7. Check `.NET SDK`, `Node.js`, and `Docker` rows reflect your actual machine state (`AlreadyPresent` with version detail, or `Warning` with a specific install link) — these are check-only by design and should never show `Installed`.

**Cleanup:** None required — the script only adds user-scoped Scoop apps/buckets, which is the intended persistent dev-environment state, not a test artifact to remove.
