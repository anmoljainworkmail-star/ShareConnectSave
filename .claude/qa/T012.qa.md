## Manual QA — T012

**Prerequisites:** `dotnet run` from `src/services/api-gateway`. No downstream services required for the 401 cases (only for the happy-path proxy check, and even then only to observe the proxy attempt — `user-service` doesn't exist yet at this phase, so expect a connection failure from YARP rather than a real 200).

1. **Public route (POST bypasses):**
   `curl -i -X POST http://localhost:8080/user/auth/google -d "{}"`
   Expect: the request is proxied past this middleware (no 401 from JWT validation) — it will then fail downstream at YARP's proxy attempt (connection-refused/502-style) since `user-service` isn't running yet. That distinction (no 401 here) is what proves the bypass worked.

2. **Public route path, wrong method (GET doesn't bypass):**
   `curl -i -X GET http://localhost:8080/user/auth/google`
   Expect: `401`, `{"code":"INVALID_TOKEN","message":"Missing or malformed Authorization header.",...}`.

3. **Protected route, no header:**
   `curl -i -X GET http://localhost:8080/user/profile`
   Expect: `401`, same "Missing or malformed Authorization header." message — rejected at the guard clause, no JWKS fetch attempted.

4. **Malformed token:**
   `curl -i -X GET http://localhost:8080/user/profile -H "Authorization: Bearer abc.def"`
   Expect: `401`, `"message":"Invalid or expired token."` — served by the catch-all fallback (`SecurityTokenMalformedException`/`ArgumentException` in the pinned library version don't derive from `SecurityTokenException`). Confirm via server log: `"JWT validation failed: unrecognized error during token parsing."`

5. **Well-formed but garbage signature (3 segments, valid base64, wrong signature):**
   `curl -i -X GET http://localhost:8080/user/profile -H "Authorization: Bearer aaa.bbb.ccc"` (or any syntactically valid but wrongly-signed JWT)
   Expect: `401` via the `SecurityTokenException` catch (`SecurityTokenInvalidSignatureException`), log line format `"JWT validation failed: {Reason}"` — distinct from step 4's catch-all log format, confirming the more specific catch still fires first for this case.

**Cleanup:** None required — this is stateless middleware, no persistent state to tear down.
