## Manual QA — T013

**Prerequisites:** No server is currently running in this session — these steps are unfollowable as-is until you start the gateway yourself: run `dotnet run --project src/services/api-gateway` (listens on `http://localhost:8080` per `Properties/launchSettings.json`). `user-service` and `connection-service` do not need to be up for the 401/429 checks below since the gateway short-circuits before proxying, but bring them up via `/docker-up` if you also want to see a real 2xx pass-through.

1. Missing/invalid Authorization header to a protected route (the fixed 401 case):
   `curl -i -X POST http://localhost:8080/connection/connections -H "Content-Type: application/json" -d "{}"`
   Expect: `HTTP/1.1 401`, JSON body `{"code":"INVALID_TOKEN",...}`, and header `X-RateLimit-Remaining: 100` present (first hit from a fresh IP).

2. Global limit → 429 (AC1): repeat any request from the same IP 101+ times within a minute, e.g.
   `for i in $(seq 1 105); do curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/discovery/health; done`
   Expect: first ~100 return whatever status the route normally returns (or 502/503 if discovery-service isn't up — that's fine, it's past the limiter by then); requests 101+ return `429` with header `X-RateLimit-Remaining: 0`.

3. Connection limit → 429 with `RATE_LIMIT_EXCEEDED` (AC2): send 11+ requests within a minute using the same `X-User-Id` header directly. This requires a valid bearer token for the first requests to get past the 401 check — if you don't have one handy from user-service, this step is not followable without it:
   `for i in $(seq 1 11); do curl -s -X POST http://localhost:8080/connection/connections -H "Authorization: Bearer <valid-jwt>" -H "Content-Type: application/json" -d '{}'; done`
   Expect: requests 1-10 proceed past the limiter (whatever status connection-service returns); request 11 returns `429` with body `{"code":"RATE_LIMIT_EXCEEDED",...}`.

4. Header present on all responses (AC3): re-run step 1 and also a normal successful request (e.g. `curl -i http://localhost:8080/discovery/health` with discovery-service up) and confirm `X-RateLimit-Remaining` appears in both the 401 case and the 2xx case.

**Cleanup:** Stop the `dotnet run` process (Ctrl+C); if you brought up the Docker stack for step 3/4, tear it down per `/docker-up`'s own instructions (`docker compose down`).
