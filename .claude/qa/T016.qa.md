## Manual QA — T016

**Prerequisites:** Stack running via `/docker-up`. A real Google ID token obtainable (e.g. via Google's OAuth Playground with this app's `GOOGLE_CLIENT_ID` as audience).

1. Start the stack (`/docker-up`), obtain a real Google ID token (e.g. via Google's OAuth Playground with this app's `GOOGLE_CLIENT_ID` as audience), POST it to `http://localhost:8081/auth/google` (direct to user-service) — confirm `200` with `access_token`/`refresh_token`/`is_new_user: true`, and a `users` row appears with `Status = incomplete`.
2. Repeat the same request with the same token/account (or a fresh token for the same Google account) — confirm `is_new_user: false` and the same user row (no duplicate), and that `Status`/`Gender` are unchanged from step 1.
3. POST with `{"id_token": ""}` and with `{}` (no field) — confirm both return `401` with body `{"code":"INVALID_GOOGLE_TOKEN", ...}`.
4. POST with a clearly garbage string as `id_token` — confirm `401` `INVALID_GOOGLE_TOKEN` (not a 500).
5. `GET /.well-known/jwks.json` — confirm `{"keys":[{...}]}` shape with `n`/`e`/`kid`/`alg: RS256`, and confirm the response contains no `d`/private-key fields.
6. Take the `access_token` from step 1 and call any gateway-proxied protected endpoint (e.g. through `api-gateway` on its port) with `Authorization: Bearer <token>` — confirm it's accepted (validates against the gateway's JWKS cache) and that `X-User-Id`/`X-User-Role`/`X-User-Gender` headers are injected downstream.
7. Restart the `user-service` container without setting `JWT__RSAPRIVATEKEYPEM` — confirm a previously issued token now fails gateway validation (expected/documented ephemeral-key behavior), and that the warning log appears without ever printing key material.
8. (Optional, targeted at the concurrent-signup race) Fire two near-simultaneous POSTs for a brand-new Google account (e.g. two curl calls launched together) — inspect whether the loser gets a clean error or a raw 500/stack trace; this exercises the known gap logged in `.claude/notes/follow-ups.md`.

**Cleanup:** `docker compose down` (or stop the stack via `/docker-up`'s teardown instructions).
