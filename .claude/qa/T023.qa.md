## Manual QA — T023

**Prerequisites:** Full local stack running via `/docker-up` (SQL Server, Redis, Kafka). Discovery Service running with `dev` profile (`DISCOVERY_DB_PASSWORD` exported). Two distinct `X-User-Id` values available (e.g., `1001` and `1002`) to simulate two travelers.

1. Start session A (near a shared route, women_only off):
   ```
   curl -i -X POST http://localhost:<discovery-port>/scan/start \
     -H "X-User-Id: 1001" -H "X-User-Gender: male" -H "Content-Type: application/json" \
     -d '{"destination_lat":40.7580,"destination_lng":-73.9855,"destination_label":"Times Square","departure_time":"2026-09-12T18:00:00Z"}'
   ```
   Expect: `201 Created`, body `{"session_id": <id-A>, "mode": "gps"}`. Note `<id-A>`.

2. Set session A's live location:
   ```
   curl -i -X PUT http://localhost:<discovery-port>/scan/location \
     -H "X-User-Id: 1001" -H "Content-Type: application/json" \
     -d '{"lat":40.7128,"lng":-74.0060}'
   ```
   Expect: `204 No Content`.

3. Start session B, ~500m away, same direction, within ±30 min:
   ```
   curl -i -X POST http://localhost:<discovery-port>/scan/start \
     -H "X-User-Id: 1002" -H "X-User-Gender: female" -H "Content-Type: application/json" \
     -d '{"destination_lat":40.7590,"destination_lng":-73.9850,"destination_label":"Times Square","departure_time":"2026-09-12T18:10:00Z"}'
   ```
   Expect: `201 Created`. Note `<id-B>`.

4. Set session B's live location (within 1km of A):
   ```
   curl -i -X PUT http://localhost:<discovery-port>/scan/location \
     -H "X-User-Id: 1002" -H "Content-Type: application/json" \
     -d '{"lat":40.7135,"lng":-74.0055}'
   ```
   Expect: `204 No Content`.

5. Query nearby from A's perspective:
   ```
   curl -s http://localhost:<discovery-port>/scan/nearby -H "X-User-Id: 1001"
   ```
   Expect: `200 OK`, JSON array containing exactly one card for user 1002 — fields `id, name, photo_url, identity_badge, distance_km` only (no `gender`, no `trust_score`, no `status`). `name`/`photo_url` will be null/omitted-defaulted if User Service isn't actually running, or if the circuit breaker fallback has no cache yet — that's expected given User Service integration isn't the focus of this ticket.

6. Repeat step 5 immediately: response should be byte-identical (served from the `scan:{id-A}:nearby` Redis cache, TTL 10s). Wait 11 seconds and repeat again — confirm at least a fresh Redis round-trip occurs (check `discovery.cache: DEBUG` logs, or `redis-cli TTL scan:<id-A>:nearby`).

7. Radius exclusion: move session B's location far away (`PUT /scan/location` with `lat:34.0522,lng:-118.2437`, Los Angeles), wait 11s (past nearby-cache TTL), repeat step 5. Expect: empty array `[]`.

8. Women-only filter: with A now `X-User-Gender: female` and `women_only: true` at start, and B's gender `male`, confirm B never appears regardless of distance (repeat steps 1-5 with genders/flags swapped accordingly).

9. `scan:active_sessions` cleanup: stop session B —
   ```
   curl -i -X POST http://localhost:<discovery-port>/scan/stop -H "X-User-Id: 1002"
   ```
   Expect: `204 No Content`. Then `redis-cli SMEMBERS scan:active_sessions` — confirm `<id-B>` is gone, and `redis-cli EXISTS scan:<id-B>:gender scan:<id-B>:women_only scan:<id-B>:location` all return `0`.

10. Failure case — missing required header:
    ```
    curl -i http://localhost:<discovery-port>/scan/nearby
    ```
    Expect: `500 Internal Server Error`, body `{"code":"INTERNAL_ERROR","message":"An unexpected error occurred.","traceId":"..."}`. (Not a 400 — this is a pre-existing gap in the shared `GlobalExceptionHandler`, not something T023 introduced; flagging so this isn't mistaken for a new bug.)

11. Failure case — no active session:
    ```
    curl -i http://localhost:<discovery-port>/scan/nearby -H "X-User-Id: 9999"
    ```
    Expect: `404 Not Found`, body `{"code":"SCAN_SESSION_NOT_FOUND","message":"No active scan session for user 9999","traceId":"..."}`.

**Cleanup:** `POST /scan/stop` for user 1001 as well; `redis-cli FLUSHDB` on logical DB 0 if you want a clean slate; stop the docker-up stack if done for the session.
