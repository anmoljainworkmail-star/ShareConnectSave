## Manual QA — T024 (v2, client-derived rotating seed)

**Prerequisites:** Discovery Service running locally via `mvn spring-boot:run` (dev profile → port 8080) against `docker-up` infra. `BLE_TOKEN_HMAC_SECRET` set to any non-empty value (required for startup — it does not affect token matching in v2, see the follow-up note on this below). Python available locally for step 3's hand-derivation (standing in for the not-yet-built client).

1. **Register a seed for user 1001.**
   ```
   curl -i -X POST http://localhost:8080/scan/ble/seed \
     -H "X-User-Id: 1001"
   ```
   Expect: `201`, body like `{"seed":"kX3f...base64url..."}`. Save this seed string — call it `SEED`.

2. **Confirm user 1001 has an active scan session** (resolve only ever matches candidates in `scan:active_sessions`; without one, step 4 will legitimately return `[]`):
   ```
   curl -i -X POST http://localhost:8080/scan/start \
     -H "X-User-Id: 1001" -H "X-User-Gender: Unspecified" \
     -H "Content-Type: application/json" \
     -d '{"destinationLat":12.9,"destinationLng":77.6,"womenOnly":false}'
   ```
   Expect: `201`. Repeat for user 2002 (the resolving user in step 4) so it also has an active session.

3. **Derive a valid broadcast value by hand**, simulating the not-yet-built client:
   ```
   window = floor(current_unix_epoch_seconds / 300)
   broadcastValue = base64url_nopad( first_16_bytes( HMAC-SHA256(key = raw_seed_bytes, message = window_as_8_big-endian_bytes) ) )
   ```
   ```python
   import base64, hashlib, hmac, time, struct
   seed_b64 = "PASTE_SEED_HERE"
   seed_bytes = base64.urlsafe_b64decode(seed_b64 + "=" * (-len(seed_b64) % 4))
   window = int(time.time()) // 300
   msg = struct.pack(">q", window)   # 8-byte big-endian long
   full = hmac.new(seed_bytes, msg, hashlib.sha256).digest()
   token = base64.urlsafe_b64encode(full[:16]).rstrip(b"=").decode()
   print(token)
   ```
   Call the output `TOKEN`.

4. **Resolve that token as user 2002.**
   ```
   curl -i -X POST http://localhost:8080/scan/ble/resolve \
     -H "X-User-Id: 2002" -H "Content-Type: application/json" \
     -d '{"tokens":["PASTE_TOKEN_HERE"]}'
   ```
   Expect: `200`, a JSON array containing one user card for user 1001, e.g. `[{"id":1001,"name":"...","photo_url":"...","identity_badge":false,"distance_km":0.03}]`.

5. **Unknown token — silent omission, no throw.**
   ```
   curl -i -X POST http://localhost:8080/scan/ble/resolve \
     -H "X-User-Id: 2002" -H "Content-Type: application/json" \
     -d '{"tokens":["not-a-real-token-AAAAAAAAAAAAAAAAAA"]}'
   ```
   Expect: `200`, `[]`.

6. **Empty tokens array — validation guard.**
   ```
   curl -i -X POST http://localhost:8080/scan/ble/resolve \
     -H "X-User-Id: 2002" -H "Content-Type: application/json" \
     -d '{"tokens":[]}'
   ```
   Expect: `400`, `{"code":"VALIDATION_ERROR","message":"...","traceId":"..."}`.

7. **Seed never re-exposed.** Inspect the response bodies from steps 2-6 and the service's stdout/log output for this whole run — the raw `SEED` from step 1 must not appear anywhere else.

8. **Blocked-candidate omission.** Requires a real block relationship via User Service's `/blocks` endpoint, which is not yet implemented (known limitation, see `UserServiceClientImpl`) — currently fails open to an empty list in this environment. Skip this step for now; note it as blocked on User Service, not a defect in this ticket.

**Cleanup:** No teardown needed — seeds and scan sessions are transient by design and self-expire (`ble.seed.ttl-minutes`, `BleTokenCleanupTask`).
