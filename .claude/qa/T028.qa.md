## Manual QA — T028

**Prerequisites:** Docker Desktop running; repo root `.env` exists with `SA_PASSWORD` set (copy from `.env.example` if missing).

1. From the repo root, run:
   `docker compose up -d sqlserver sqlserver-init redis kafka discovery-service`
   Expect: Compose creates and starts `sqlserver`, `redis`, `kafka`, runs `sqlserver-init` to completion (exits 0), then starts `discovery-service`.

2. Run:
   `docker compose ps`
   Expect: `discovery-service` row shows `STATUS` progressing from `Up X seconds (health: starting)` to `Up X seconds (healthy)` within about 60-90 seconds, on `PORTS` `0.0.0.0:8082->8080/tcp`.

3. Run:
   `curl http://localhost:8082/actuator/health`
   Expect: HTTP 200 with a JSON body whose top-level `"status"` field is `"UP"`.

4. Run:
   `docker logs discovery-service --tail 30`
   Expect: a line reading `Started DiscoveryServiceApplication in <N> seconds`, and no `ERROR`/stack-trace lines about SQL Server login failure (18456) or Kafka connection refusal.

5. Build the image standalone and check its size:
   `docker build -f src/services/discovery-service/Dockerfile -t discovery-service:qa src/services`
   then `docker inspect --format "{{.Size}}" discovery-service:qa`
   Expect: a byte count under 300000000 (300MB). Note: `docker images discovery-service:qa` may show a much larger number (e.g. ~450MB) on Docker Desktop installations using the containerd image store — this is a known display quirk, not the real size; trust `docker inspect`'s `.Size` field or `docker save discovery-service:qa -o test.tar` followed by checking the resulting file size instead.

**Cleanup:** `docker compose down` (removes the containers and the compose network; named volumes for sqlserver/redis/kafka are preserved unless `-v` is also passed). Remove the standalone QA image with `docker rmi discovery-service:qa` and delete any `test.tar` you created in step 5.
