## Manual QA — T029

**Prerequisites:** Docker Desktop running; `docker-up` completed (SQL Server + Kafka reachable); JDK 21 on PATH; run all commands from `src/services/connection-service`.

1. From `src/infra`, confirm infra is up:
   ```
   docker compose ps
   ```
   Expect: `sqlserver` shows `healthy`, `sqlserver-init` shows `Exited (0)`.

2. Export the required env vars (bare `mvn spring-boot:run` does not pick up a profile by itself — this must be set explicitly, same gotcha as T021):
   ```
   set SPRING_PROFILES_ACTIVE=dev
   set CONNECTION_DB_PASSWORD=<the sa password from your .env>
   ```
   Leave `CONNECTION_DB_HOST`/`PORT`/`NAME` unset unless your compose mapping differs — defaults are `localhost:14330`/`ConnectionServiceDb`.

3. Run the service:
   ```
   mvn spring-boot:run
   ```
   Expect: log lines showing Flyway applying `V001__connection_service_initial_schema.sql`, followed by `Tomcat started on port 8080`.
   Failure signs: `Could not resolve placeholder 'CONNECTION_DB_PASSWORD'` → step 2 was skipped. `Login failed for user 'sa'` → password doesn't match `sqlserver-init`'s actual value.

4. Confirm health:
   ```
   curl http://localhost:8080/actuator/health
   ```
   Expect: exactly `{"status":"UP"}` — no nested `components` object (that would mean `show-details` drifted from the default `never`).

5. Confirm Flyway actually applied `V001` (not just "didn't error"): connect to SQL Server (e.g. via `sqlcmd` or Azure Data Studio) against `ConnectionServiceDb` on `localhost,14330` and run:
   ```sql
   SELECT * FROM flyway_schema_history;
   SELECT * FROM connection_requests; -- should exist and be empty
   ```
   Expect: one row in `flyway_schema_history` for version `1`, `success = 1`; `connection_requests` table exists with the five indexes from V001.

6. Confirm idempotent restart: stop the service (Ctrl+C), run `mvn spring-boot:run` again. Expect: no checksum-mismatch or re-apply error — Flyway logs that the schema is already current.

**Cleanup:** Stop the running process (Ctrl+C). Optionally `docker compose down` from `src/infra` if the infra isn't needed for anything else.
