## Manual QA — T034

**Prerequisites:** Docker Desktop (or equivalent engine) running; a `.env` file exists at the repo root with a real `SA_PASSWORD` set (copy from `.env.example` if missing); the shared infra stack (SQL Server, Kafka) is reachable — either already up via `/docker-up` or about to be started fresh.

1. From the repo root, run:
   ```
   docker compose -f src/infra/docker-compose.yml -f src/infra/docker-compose.override.yml up -d sqlserver sqlserver-init kafka
   ```
   Expect: `sqlserver` and `kafka` reach `healthy` status, `sqlserver-init` exits `0` (completed). Check with `docker compose -f src/infra/docker-compose.yml ps` — status column shows `healthy` for sqlserver/kafka and `exited (0)` for sqlserver-init.

2. Build the connection-service image:
   ```
   docker compose -f src/infra/docker-compose.yml -f src/infra/docker-compose.override.yml build connection-service
   ```
   Expect: build completes with no errors, ending in a line like `=> => naming to docker.io/shareconnectsave/connection-service:dev`. A Maven compile failure or missing-file error here is a FAIL.

3. Start the service:
   ```
   docker compose -f src/infra/docker-compose.yml -f src/infra/docker-compose.override.yml up -d connection-service
   ```
   Expect: command returns immediately with `Container connection-service Started` (or `Healthy` if it waits).

4. Check health status:
   ```
   docker compose -f src/infra/docker-compose.yml ps connection-service
   ```
   Expect: `STATUS` column eventually reads `Up X seconds (healthy)` — allow up to the `start_period: 60s` configured in the healthcheck before expecting `healthy`. If it reads `(unhealthy)` or the container is `Restarting`, that's a FAIL — go to step 5.

5. If unhealthy, check logs:
   ```
   docker compose -f src/infra/docker-compose.yml logs connection-service --tail=100
   ```
   Expect (healthy case): log lines showing a clean Spring Boot startup, a successful SQL Server login to `ConnectionServiceDb` (no `Login failed for user` / error 18456), and the Kafka consumer joining group `connection-service`. Any `Login failed for user ''` line specifically means `SA_PASSWORD` or the username/password override env vars are missing or wrong — re-check `.env` and `docker-compose.override.yml:121-122`.

6. Directly confirm the health endpoint from the host:
   ```
   curl -f http://localhost:8083/actuator/health
   ```
   Expect: HTTP 200 with a JSON body containing `"status":"UP"`.

7. (Optional, confirms the multi-stage build actually slimmed the image) Check true image size:
   ```
   docker inspect shareconnectsave/connection-service:dev --format "{{.Size}}"
   ```
   Expect: a byte count translating to roughly 130-160MB — consistent with discovery-service's T028 result. Do **not** use `docker images` for this check — the ticket notes it reports a misleadingly larger number (~400MB+) due to a known containerd-snapshotter display quirk.

**Cleanup:**
```
docker compose -f src/infra/docker-compose.yml -f src/infra/docker-compose.override.yml down
```
(Add `-v` only if you also want to wipe the SQL Server/Kafka data volumes — not necessary just to tear down this check.)
