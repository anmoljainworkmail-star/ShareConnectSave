## Manual QA — T035

**Prerequisites:** Docker Desktop running; repo at `C:\Users\anmol.jain\Downloads\ShareConnectSave`.

1. **Confirm infra is up.**
   ```powershell
   cd C:\Users\anmol.jain\Downloads\ShareConnectSave\src\infra
   docker compose ps
   ```
   Expected: `mongodb` container shows `Up (healthy)`. If not running, start it with `/docker-up` or `docker compose up -d mongodb`.

2. **Build the service.**
   ```powershell
   cd C:\Users\anmol.jain\Downloads\ShareConnectSave\src\services\chat-service
   dotnet build
   ```
   Expected: `Build succeeded. 0 Warning(s) 0 Error(s)`.

3. **Start chat-service with default TTL (7200s).**
   ```powershell
   $env:ConnectionStrings__ChatDb = "mongodb://localhost:27017/ChatServiceDb"
   dotnet run
   ```
   Expected (healthy): console shows `Now listening on: http://localhost:<port>` with no exception. Failure looks like: an unhandled `InvalidOperationException` mentioning `ConnectionStrings__ChatDb` (means Mongo config missing) or a `MongoConnectionException` / timeout (means the `mongodb` container isn't reachable at that host/port — check step 1).

4. **Verify the TTL index exists via mongosh.**
   In a second terminal:
   ```powershell
   docker exec -it <mongodb-container-name> mongosh "mongodb://localhost:27017/ChatServiceDb"
   ```
   Then inside `mongosh`:
   ```js
   db.messages.getIndexes()
   ```
   Expected (healthy): one entry with `"key": { "sent_at": 1 }` and `"expireAfterSeconds": 7200`. Failure looks like: only the default `_id_` index present (TTL index was never created — check service startup logs for an exception before `Now listening on`).

5. **Verify restart doesn't error (idempotency check).**
   Stop the service (`Ctrl+C` in the `dotnet run` terminal), then run `dotnet run` again with the same env var set.
   Expected (healthy): service starts cleanly again, no exception, and `db.messages.getIndexes()` in `mongosh` still shows exactly **one** `sent_at` index (not two). Failure looks like: a duplicate index, or an `IndexOptionsConflict` exception on startup.

6. **Verify changing the TTL value triggers drop+recreate correctly.**
   Stop the service. Set a different TTL and restart:
   ```powershell
   $env:MONGO_TTL_SECONDS = "3600"
   dotnet run
   ```
   Then back in `mongosh`:
   ```js
   db.messages.getIndexes()
   ```
   Expected (healthy): the `sent_at` index now shows `"expireAfterSeconds": 3600` (old one was dropped and replaced, not duplicated).

7. **Verify the guard clause for a missing connection string.**
   Stop the service, unset the env var, and try to start:
   ```powershell
   Remove-Item Env:\ConnectionStrings__ChatDb -ErrorAction SilentlyContinue
   dotnet run
   ```
   Expected (healthy): immediate, clear exception: `ConnectionStrings__ChatDb is not set` — service does not hang or partially start.

8. **Confirm `appsettings.json` has no stray fallback value.** Open `src/services/chat-service/appsettings.json` and `appsettings.Development.json` and confirm neither contains a `ConnectionStrings:ChatDb` key with a real value — only structure/no secrets, per project convention. (Reviewed already during `/review-task`: both files contain only `Logging`/`AllowedHosts` — no stray key present.)

9. **Health check.**
   ```powershell
   curl http://localhost:<port>/health
   ```
   Expected: `200 OK`, empty body.
