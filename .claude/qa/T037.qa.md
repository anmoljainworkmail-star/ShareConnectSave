## Manual QA — T037

**Prerequisites:** `/docker-up` stack running (MongoDB reachable), chat-service built and running locally or in Compose, and an existing `chat_rooms` document already in `OPEN` status for a known `connection_id` (create one via `mongosh` if T038 isn't wired up yet — see step 1). You need two user ids to act as the chat's two participants (e.g. `1001` and `1002`).

1. Seed a test room directly in Mongo (since T038's `connection.accepted` consumer may not exist yet):
   ```
   mongosh "<chat-service Mongo connection string>" --eval '
   db.chat_rooms.insertOne({
     connection_id: "test-conn-1",
     user_a_id: NumberLong(1001),
     user_b_id: NumberLong(1002),
     status: "OPEN",
     created_at: new Date(),
     closed_at: null,
     user_a_met_at: null,
     user_b_met_at: null,
     outbox_event_type: null,
     outbox_payload: null,
     outbox_created_at: null,
     outbox_published_at: null
   })'
   ```
   Expect: insert acknowledged, note the returned `_id` as `<CHAT_ID>`.

2. Call "met" as the first user:
   ```
   curl -i -X POST http://localhost:<chat-service-port>/chats/<CHAT_ID>/met -H "X-User-Id: 1001"
   ```
   Expect: `200 OK`, body `{"chat_id":"<CHAT_ID>","both_users_met":false}`.

3. Confirm in Mongo that only `user_a_met_at` was set and `status` is still `OPEN`:
   ```
   mongosh "<conn string>" --eval 'db.chat_rooms.findOne({_id: ObjectId("<CHAT_ID>")})'
   ```
   Expect: `user_a_met_at` is a timestamp, `user_b_met_at` is `null`, `status` is `"OPEN"`.

4. Call "met" as the second user:
   ```
   curl -i -X POST http://localhost:<chat-service-port>/chats/<CHAT_ID>/met -H "X-User-Id: 1002"
   ```
   Expect: `200 OK`, body `{"chat_id":"<CHAT_ID>","both_users_met":true}`.

5. Immediately check Mongo — status should now be `CLOSING` (grace timer just started):
   ```
   mongosh "<conn string>" --eval 'db.chat_rooms.findOne({_id: ObjectId("<CHAT_ID>")}, {status:1, user_a_met_at:1, user_b_met_at:1})'
   ```
   Expect: `status: "CLOSING"`, both `*_met_at` fields set.

6. Wait for the grace period to elapse (default 300s, or set `CHAT_MET_GRACE_PERIOD_SECONDS=10` in your local env before starting the service to speed this up), then re-check Mongo:
   ```
   mongosh "<conn string>" --eval 'db.chat_rooms.findOne({_id: ObjectId("<CHAT_ID>")})'
   ```
   Expect: `status: "CLOSED"`, `closed_at` set, `outbox_event_type: "chat.closed"`, `outbox_payload` is a JSON string containing `"closed_reason":"met_successfully"`, `outbox_published_at: null` (not yet relayed — that's T039's job, not observable until then).

7. Confirm messages were explicitly deleted (not just left for TTL):
   ```
   mongosh "<conn string>" --eval 'db.messages.find({chat_id: "<CHAT_ID>"}).count()'
   ```
   Expect: `0` (even if you sent test messages into this room earlier via T036's endpoints before closing).

8. Test the auto-close path: seed a second room with `created_at` backdated past the threshold:
   ```
   mongosh "<conn string>" --eval '
   db.chat_rooms.insertOne({
     connection_id: "test-conn-2",
     user_a_id: NumberLong(2001),
     user_b_id: NumberLong(2002),
     status: "OPEN",
     created_at: new Date(Date.now() - 1000*60*60*3),
     closed_at: null, user_a_met_at: null, user_b_met_at: null,
     outbox_event_type: null, outbox_payload: null, outbox_created_at: null, outbox_published_at: null
   })'
   ```
   Wait up to one poll interval (default 300s, or set `CHAT_AUTO_CLOSE_POLL_INTERVAL_SECONDS=10` locally), then re-check:
   ```
   mongosh "<conn string>" --eval 'db.chat_rooms.findOne({connection_id: "test-conn-2"})'
   ```
   Expect: `status: "CLOSED"`, `outbox_payload` contains `"closed_reason":"timeout"`.

9. Test the failure path — non-participant calls "met":
   ```
   curl -i -X POST http://localhost:<chat-service-port>/chats/<CHAT_ID>/met -H "X-User-Id: 9999"
   ```
   Expect: `403 Forbidden`, body `{"code":"NOT_A_PARTICIPANT","message":"You are not a participant in this chat.","traceId":"<some-id>"}`.

10. Test missing identity header:
    ```
    curl -i -X POST http://localhost:<chat-service-port>/chats/<CHAT_ID>/met
    ```
    Expect: `401 Unauthorized`, body `{"code":"MISSING_IDENTITY","message":"X-User-Id header is missing or invalid.","traceId":"<some-id>"}`.

11. Test already-closed room:
    ```
    curl -i -X POST http://localhost:<chat-service-port>/chats/<CHAT_ID>/met -H "X-User-Id: 1001"
    ```
    (using the room closed in step 6) Expect: `409 Conflict`, body `{"code":"CHAT_ALREADY_CLOSED","message":"This chat has already closed.","traceId":"<some-id>"}`.

**Note:** You will NOT see an actual message on a Kafka topic for `chat.closed` at this stage — that relay is T039's responsibility, not yet implemented. Steps 6 and 8 above (checking the `outbox_*` fields directly in Mongo) are the correct way to verify this ticket's event-publishing behavior until T039 ships.

**Cleanup:**
```
mongosh "<conn string>" --eval 'db.chat_rooms.deleteMany({connection_id: {$in: ["test-conn-1","test-conn-2"]}})'
```
If you overrode any `CHAT_*` env vars for faster testing, restore the Compose defaults (`docker-compose.override.yml` lines 153-155) before further testing, or restart the stack with `docker compose down && /docker-up`.
