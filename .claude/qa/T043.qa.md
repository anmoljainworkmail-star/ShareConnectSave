## Manual QA — T043

**Prerequisites:** JDK 21 and Maven installed; no database, Kafka, or Docker services need to be running — this ticket has zero I/O.

Per project policy, no test file ships with this ticket — automated unit tests for `TrustScoreCalculator` are written in the batch-testing phase (T081). This checklist verifies the algorithm manually via `jshell` instead.

1. Compile the module and launch `jshell` against its classes:
   ```
   cd src/services/rating-service
   mvn -q compile
   jshell --class-path target/classes
   ```

2. In `jshell`, import the domain classes and construct a calculator:
   ```java
   import com.shareconnectsave.rating.domain.*;
   import java.time.Instant;
   import java.time.temporal.ChronoUnit;
   import java.util.List;
   var calc = new TrustScoreCalculator();
   ```

3. **New user (no ratings)** — expect score `5.0`, badge `NONE`, requestLimit `UNLIMITED`:
   ```java
   calc.calculate(List.of(), 0)
   ```

4. **High score, badge-eligible** — 10 perfect ratings, no negative tags — expect score `5.0`, badge `TRUSTED`, requestLimit `UNLIMITED`:
   ```java
   var now = Instant.now();
   var goodRatings = java.util.stream.IntStream.range(0, 10)
       .mapToObj(i -> new RatingSnapshot(now.minus(10 - i, ChronoUnit.DAYS), List.of(RatingTag.FRIENDLY)))
       .toList();
   calc.calculate(goodRatings, 0)
   ```

5. **Nine ratings — just below the badge count threshold** — same as above but 9 entries — expect badge `NONE` (score still `5.0`, requestLimit still `UNLIMITED`):
   ```java
   calc.calculate(goodRatings.subList(0, 9), 0)
   ```

6. **Low score via severe negative tags** — a user with `ABUSIVE` tags on every rating — expect score at/near `1.0` (floor), requestLimit `SUSPENDED`:
   ```java
   var badRatings = java.util.stream.IntStream.range(0, 5)
       .mapToObj(i -> new RatingSnapshot(now.minus(5 - i, ChronoUnit.DAYS), List.of(RatingTag.ABUSIVE)))
       .toList();
   calc.calculate(badRatings, 0)
   ```

7. **Suspension via report count overriding a perfect score** — expect requestLimit `SUSPENDED` even though the score is `5.0`:
   ```java
   calc.calculate(goodRatings, 3)
   ```

8. **Throttle boundary — score exactly 2.5** — construct a single rating whose `ratingValue()` lands at 2.5 (e.g. two `DIDNT_SHOW_UP`-style standard negatives: `5.0 - 1.0 - 1.0 = 3.0`; adjust tags until the printed score reads `2.5`, or inspect `ratingValue()`'s math directly) — expect requestLimit `THROTTLED`, not `SUSPENDED`:
   ```java
   var borderline = List.of(new RatingSnapshot(now, List.of(RatingTag.DIDNT_SHOW_UP, RatingTag.SPAM, RatingTag.FAKE_DESTINATION)));
   calc.calculate(borderline, 0)
   ```
   Expect printed `score` to equal `2.0` here (5.0 − 1.0 − 1.0 − 1.0, floored at `MIN_RATING_VALUE`); adjust the tag combination until you've independently observed one case landing below 2.5 (`SUSPENDED`) and one at/above it (`THROTTLED`/`UNLIMITED`) to confirm the boundary is a strict `<`, not `<=`.

9. **`RequestLimit.wireValue()` boundary mapping** — expect `2147483647`, `3`, `0`:
   ```java
   RequestLimit.UNLIMITED.wireValue()
   RequestLimit.THROTTLED.wireValue()
   RequestLimit.SUSPENDED.wireValue()
   ```

10. Run the full module build to confirm nothing else in rating-service regressed:
    ```
    mvn -pl src/services/rating-service -am test
    ```
    Expect: `BUILD SUCCESS` (no test files exist yet for this module beyond the T041 `RatingServiceApplicationTests` smoke test).

**Cleanup:** No services were started and no state was persisted — nothing to tear down. Exit `jshell` with `/exit`.
