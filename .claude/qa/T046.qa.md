## Manual QA — T046

**Prerequisites:** Docker Desktop running; `.env` present in `src/infra/` with `SA_PASSWORD` and `KAFKA_BOOTSTRAP` set (copy from `.env.example` if missing); the rest of the stack (`sqlserver`, `kafka`) already started via `docker compose up -d sqlserver sqlserver-init kafka kafka-init` or `/docker-up`.

1. From `src/infra/`, run:
   `docker compose build rating-service`
   Expect: build completes with no errors; final log line resembles `Successfully built` / `writing image sha256:...`; no "could not resolve dependency" or "COPY failed: file not found" errors referencing `shared-java-lib`.

2. Run:
   `docker compose up -d rating-service`
   Expect: command returns immediately; `rating-service` container is created.

3. Run:
   `docker compose ps rating-service`
   Expect: `STATUS` column eventually shows `Up ... (healthy)` within ~60s (healthcheck `start_period: 60s`). A `(health: starting)` status briefly is normal; `(unhealthy)` or `Restarting` is a failure.

4. Run:
   `docker compose logs rating-service --tail=50`
   Expect: log lines showing Flyway migrating `RatingServiceDb` successfully, Spring Boot's startup banner, and three Kafka consumer group-join lines for `ChatClosedConsumer`, `RatingSubmittedConsumer`, `ReportFiledConsumer` under group id `rating-service`. No `Login failed for user ''` (SQL 18456) and no `Could not resolve placeholder 'BLE_TOKEN_HMAC_SECRET'`-style errors.

5. Run:
   `curl -f http://localhost:8085/actuator/health`
   Expect: HTTP 200 with body `{"status":"UP", ...}`. A connection-refused or non-200 response is a failure.

6. Verify authoritative image size (NOT `docker images`):
   `docker inspect --format "{{.Size}}" shareconnectsave/rating-service:dev`
   Expect: a byte count under `300000000` (300MB). Current recorded value is ~139,834,321 bytes (~133MB) — a large deviation upward (e.g., back toward 300MB+) would be worth investigating before trusting this AC again.

7. Cross-check with a second authoritative method:
   `docker save shareconnectsave/rating-service:dev -o rating-image.tar` then check the file size (`ls -la rating-image.tar` or `Get-Item rating-image.tar | Select Length` in PowerShell).
   Expect: a size close to step 6's number (within a few MB) — confirms `docker inspect` isn't itself misleading. Delete `rating-image.tar` afterward.

8. (Optional sanity check on the context fix) Run:
   `docker compose config rating-service`
   Expect: the rendered config shows `build.context` resolving to the `src/services` parent directory and `build.dockerfile: rating-service/Dockerfile` — confirming the shared-lib-aware context is actually what Compose will use, not the narrower one the ticket file still describes.

**Cleanup:** `docker compose stop rating-service && docker compose rm -f rating-service` (leaves the rest of the stack, e.g. `sqlserver`/`kafka`, untouched). Remove `rating-image.tar` if created in step 7.
