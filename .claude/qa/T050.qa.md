## Manual QA — T050

**Prerequisites:** Docker Desktop running; repo cloned.

1. **One-time setup (new clone only):** Confirm `src/infra/secrets/fcm-service-account.json` exists; if missing, create a dummy JSON (or point `FCM_CREDENTIALS_JSON_HOST_PATH` at a real one) **before** `docker compose up`, per `.claude/qa/T047.qa.md:5`. Skipping this reproduces the original empty-directory crash.
2. `docker compose build notification-service` → expect success, no MSB4018.
3. `docker compose up -d notification-service` → expect `(healthy)` within ~40s.
4. `curl.exe -i http://localhost:8086/health` → expect `HTTP/1.1 200 OK`.
5. `docker inspect shareconnectsave/notification-service:dev --format='{{.Size}}'` → expect under `200000000`.
6. `docker compose down && docker compose up -d notification-service` (cold cycle) → expect same `(healthy)` result, confirming step 1 wasn't a warm-cache fluke.

**Cleanup:** `docker compose down` (add `-v` only if you also want to drop SQL Server/Mongo/Kafka volumes).
