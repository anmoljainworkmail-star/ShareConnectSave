## Manual QA — T056

**Prerequisites:** admin-service builds and runs locally (`mvn spring-boot:run` from `src/services/admin-service`, `dev` profile active) on its default port (check `server.port` / default 8080 if unset — no explicit port override was found in `application.yml`, so confirm the actual bound port from the startup log before running these). No other infrastructure (SQL Server, Kafka, Redis) is required — this service has no datasource or broker.

1. Start the service and confirm it logs successful startup with no bean-wiring errors (particularly around `SecurityConfig`, `AdminRoleAuthenticationFilter`, `AdminAuthenticationEntryPoint`, `AdminAccessDeniedHandler` — a missing `ObjectMapper` bean or a circular dependency would fail here).
   Expect: `Started AdminServiceApplication in ... seconds`, no stack trace.

2. Request with no `X-User-Role` header at all:
   ```
   curl -i http://localhost:8080/admin/ping
   ```
   Expect: HTTP `403 Forbidden`, body `{"code":"FORBIDDEN","message":"Admin role required","traceId":""}`.

3. Request with `X-User-Role: admin`:
   ```
   curl -i -H "X-User-Role: admin" http://localhost:8080/admin/ping
   ```
   Expect: HTTP `200 OK`, body `pong`.

4. Request with `X-User-Role: user` (wrong role, present but not admin):
   ```
   curl -i -H "X-User-Role: user" http://localhost:8080/admin/ping
   ```
   Expect: HTTP `403 Forbidden`, same envelope as step 2.

5. Request with wrong-case role (`X-User-Role: Admin`) — confirms the case-sensitive match is real, not accidentally case-insensitive:
   ```
   curl -i -H "X-User-Role: Admin" http://localhost:8080/admin/ping
   ```
   Expect: HTTP `403 Forbidden`, same envelope as step 2.

6. Request to `/actuator/health` with no header at all:
   ```
   curl -i http://localhost:8080/actuator/health
   ```
   Expect: HTTP `200 OK`, body `{"status":"UP"}` (no `X-User-Role` required — confirms the `permitAll()` carve-out works).

7. Confirm the body shape in steps 2, 4, 5 is byte-identical across all three (paste all three bodies side by side) — this is the concrete check behind AC3; a difference here would mean the entry point and access-denied handler have drifted apart.

**Cleanup:** stop the service (`Ctrl+C` in the terminal running `spring-boot:run`); no state was persisted anywhere (no DB, no files written), so nothing else needs to be reset.
