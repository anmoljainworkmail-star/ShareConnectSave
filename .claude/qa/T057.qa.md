## Manual QA — T057

**Prerequisites:**
- `docker-up` infra running (MongoDB, Kafka, Kafka UI). admin-service has **no Dockerfile yet** (T061 pending) — run locally: `cd src/services/admin-service && ./mvnw spring-boot:run -Dspring-boot.run.profiles=dev` (binds `localhost:8080`).
- **Known limitation:** User Service lacks the suspend/account-status endpoints and Report Service lacks the per-user report-history endpoint. Steps 1 and 4 will fail against the real stack today for that reason (not a T057 defect) — included to confirm the failure mode is the documented clean one, not a crash/hang.

1. `curl -i http://localhost:8080/admin/queue -H "X-User-Role: admin"`
   Expect (today): `500` `{"code":"INTERNAL_ERROR",...}` (User Service endpoint doesn't exist). Once T059 ships: `200` with JSON array of suspended users.
2. `curl -i http://localhost:8080/admin/users/1 -H "X-User-Role: admin"` (use a real existing numeric id)
   Expect: `200 OK` with `userId`, `displayName`, `status`, `profileUnavailable: false`, `trustScore`/`trustScoreUnavailable`; `reportHistory: []` with `reportHistoryUnavailable: true` (expected degradation, not a bug).
3. `curl -i http://localhost:8080/admin/users/999999999 -H "X-User-Role: admin"`
   Expect: `404` `{"code":"USER_NOT_FOUND","message":"No user found with id 999999999","traceId":""}`.
4. `curl -i -X POST http://localhost:8080/admin/users/1/reinstate -H "X-User-Role: admin" -H "X-User-Id: admin-1"`
   Expect (today): `500` (User Service's account-status endpoint missing). Once it ships: `200` `{"userId":"1","status":"active","updatedAt":"..."}`.
5. Repeat step 4 without `X-User-Id`. Expect: `500` (matches documented gap #4, not a regression).
6. `curl -i http://localhost:8080/admin/queue` with no `X-User-Role` header.
   Expect: `403` `{"code":"FORBIDDEN","message":"Admin role required","traceId":""}`.
7. Once step 4 succeeds end-to-end: open Kafka UI, topic `trust.score.updated`, Messages tab.
   Expect: a new message keyed by `userId` within ~500ms, body `{"event_id":...,"user_id":"1","new_score":<num>,"badge_level":"trusted"|"standard","request_limit":<int>}`.
8. Inspect Mongo (`mongodb://localhost:27018/AdminServiceDb`, collection `admin_outbox`) and confirm the row from step 7 has a non-null `publishedAt` shortly after the Kafka UI message appeared.

**Cleanup:** stop the local `mvnw spring-boot:run` process (Ctrl+C); no `docker compose down` needed since admin-service wasn't containerized for this pass.
