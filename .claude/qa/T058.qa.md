## Manual QA — T058

**Prerequisites:** admin-service built and runnable locally (`mvn spring-boot:run` from
`src/services/admin-service`, or via Docker Compose once wired); no live Rating Service
instance required since the call is stubbed. These steps were written to be run as-is — no
running instance was available in the review environment, so none of this was executed yet.

1. Start admin-service locally on its configured port (check `application.yml` for the port,
   e.g. `8080`).
   Expect: service starts without error; `/actuator/health` returns `200 OK` with no auth
   headers required.

2. Send a valid override request:
   ```
   curl -i -X PATCH http://localhost:8080/admin/users/42/trust-score \
     -H "X-User-Id: admin-007" \
     -H "X-User-Role: admin" \
     -H "Content-Type: application/json" \
     -d '{"score": 3.8, "reason": "Manually cleared after confirmed false mass-report"}'
   ```
   Expect: `200 OK`, JSON body shaped like
   `{"userId":"42","score":3.8,"reason":"Manually cleared after confirmed false mass-report","auditId":"<uuid>","overriddenBy":"admin-007","overriddenAt":"<ISO-8601 timestamp>"}`.

3. Check the admin-service application log output from step 2.
   Expect: a `WARN`-level line from `RatingServiceClientImpl` reading something like
   `Rating Service PATCH /trust/42 is stubbed (T058) — echoing override locally, no real
   upstream call made: score=3.8, reason=Manually cleared...` — this confirms no real
   network call was attempted, and is the only way to observe the stub firing (there's no
   live endpoint to hit).

4. Open `RatingServiceClientImpl.java` and visually confirm the TODO marker is present and
   unambiguous.
   Expect: a comment block directly above `overrideTrustScore` containing the text
   `TODO: Rating Service has no PATCH /trust/:userId yet — stubbed until that ticket ships`
   (or equivalent wording naming T058 and the missing endpoint).

5. Inspect the in-memory audit log's effect.
   Expect: there is currently **no debug/inspection HTTP endpoint** exposed for
   `TrustScoreOverrideAuditLog` (`findAll()` exists on the class but nothing calls it from a
   controller yet). The only way to verify the entry was recorded in this environment is
   indirectly: the `auditId` returned in step 2's response body is non-null and a valid UUID,
   which only happens if `auditLog.record(...)` executed successfully before the response was
   built. Do not invent a debug endpoint to check this — none exists yet.

6. Send a request with a blank reason (boundary case):
   ```
   curl -i -X PATCH http://localhost:8080/admin/users/42/trust-score \
     -H "X-User-Id: admin-007" \
     -H "X-User-Role: admin" \
     -H "Content-Type: application/json" \
     -d '{"score": 3.8, "reason": ""}'
   ```
   Expect: `400 Bad Request` with body `{"code":"VALIDATION_ERROR","message":"<bean
   validation message for blank reason>","traceId":""}`.

7. Send a request missing the `X-User-Role` header entirely (non-admin case):
   ```
   curl -i -X PATCH http://localhost:8080/admin/users/42/trust-score \
     -H "X-User-Id: admin-007" \
     -H "Content-Type: application/json" \
     -d '{"score": 3.8, "reason": "test"}'
   ```
   Expect: `403 Forbidden` (via `AdminAccessDeniedHandler`/`AdminAuthenticationEntryPoint`
   since `SecurityConfig` requires `ROLE_ADMIN` for every path except `/actuator/health`) —
   exact body shape depends on `AdminAccessDeniedHandler`'s implementation; confirm it still
   returns a `{code, message, traceId}`-shaped envelope rather than Spring Boot's default
   whitelabel error page.

**Cleanup:** stop the local admin-service process (Ctrl+C or `docker compose down` if run via
Compose). No database state to clean up — the audit log is in-memory and resets on restart.

**Known non-blocking issues to watch for while testing (see `.claude/notes/follow-ups.md`
"From T058"):**
- An out-of-range `score` (e.g. `-500` or `99999`) is currently accepted, not rejected — not
  a bug for this ticket's acceptance criteria, but don't be surprised if step 2 "succeeds"
  with a nonsensical score.
- A missing `X-User-Id` header (unlike missing `X-User-Role`) returns `500 INTERNAL_ERROR`,
  not a clean `400` — pre-existing shared-java-lib gap, not specific to this endpoint.
