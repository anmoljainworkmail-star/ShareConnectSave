## Manual QA — T060

**Prerequisites:** `docker-up` infra running (Mongo, Kafka not required for this endpoint but part of the shared stack); admin-service, user-service, discovery-service, connection-service, report-service all running locally (ports per each service's `application.yml` dev profile, gateway not required — call admin-service directly on its mapped host port, e.g. `localhost:8087` — substitute the actual mapped port from `src/infra/docker-compose.yml` if different).

1. `curl -i http://localhost:8087/admin/stats` (no `X-User-Role` header)
   Expect: `403 Forbidden` with an error envelope body `{ "code": ..., "message": ..., "traceId": ... }` (via `AdminAccessDeniedHandler`/`AdminAuthenticationEntryPoint`) — confirms `/admin/stats` is not accidentally `permitAll()`.

2. `curl -i -H "X-User-Role: admin" http://localhost:8087/admin/stats`
   Expect: `200 OK`, JSON body containing all 5 fields: `totalActiveUsers`, `totalScansToday`, `totalConnectionsAcceptedToday`, `totalReportsToday`, `topReportedUsers` (array, up to 5 entries of `{reportedId, reportCount}`), plus the five `...Unavailable` boolean siblings. Given Report Service has no `GET /reports` yet, expect `totalReportsToday: null, totalReportsTodayUnavailable: true` — this is the documented KNOWN GAP, not a bug.

3. Immediately repeat step 2's exact same curl command.
   Expect: identical response returned near-instantly (cache hit) — use `time curl ...` on both calls and confirm the second call is noticeably faster (no downstream fan-out) IF the first call's response had all `...Unavailable` flags `false`. If step 2 showed `totalReportsTodayUnavailable: true`, the response is **not** cached by design (per `isFullyAvailable()`), so this repeat will be just as slow as step 2 — that is expected given the current KNOWN GAP, not a failure of AC2.

4. Stop discovery-service, then repeat step 2 (with a fresh cache — wait >60s since the last fully-available call, or restart admin-service to clear the in-memory cache).
   Expect: `200 OK` still returned (not a 500), with `totalScansToday: null, totalScansTodayUnavailable: true`, and the other 3 real metrics still populated normally — confirms Partial-Failure Degradation isolates the one dead dependency.

5. Restart discovery-service, wait for it to report healthy, then repeat step 2 again.
   Expect: `totalScansToday` back to a real number, `totalScansTodayUnavailable: false` — confirms recovery is picked up on the next request rather than staying stuck on a cached degraded snapshot.

**Cleanup:** restart any services stopped in step 4 if not already done in step 5; `docker compose down` if the infra stack was started solely for this QA pass.
