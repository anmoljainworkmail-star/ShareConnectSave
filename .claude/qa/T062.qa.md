## Manual QA — T062

**Prerequisites:** Node tooling installed, `npm install` run in `src/frontend`, a static file server available (e.g. `npx http-server` or `npx serve`), Chrome (desktop or Android) for Lighthouse.

1. `cd src/frontend && npx ng build --configuration production` / Expect: build succeeds, output in `dist/frontend/browser`, `ngsw.json` and `ngsw-worker.js` present in that folder (service worker only gets generated for a real `serviceWorker: true`-equivalent prod build, not `ng serve`).
2. Serve the build with a real HTTP server — service workers require an actual origin, not `file://` and not plain `ng serve` (which doesn't register the worker by default): `npx http-server dist/frontend/browser -p 8080` / Expect: server starts, reachable at `http://localhost:8080`.
3. Open `http://localhost:8080` in Chrome, open DevTools → Application → Service Workers / Expect: a service worker is registered and activated for that origin; Application → Manifest shows the parsed `manifest.webmanifest` with icons loading correctly from `public/icons/`.
4. Run a Lighthouse PWA audit via CLI (Lighthouse v10+ removed the PWA category checkbox from the DevTools GUI — must use CLI or `--only-categories`): `npx lighthouse http://localhost:8080 --only-categories=pwa --view` / Expect: installability, manifest, and service-worker checks pass; review any failed audits before sign-off.
5. Test installability as a desktop-Chrome proxy for Android: in Chrome's address bar look for the install icon (or DevTools → Application → Manifest → "Add to homescreen" prompt simulation) / Expect: install prompt is offered (confirms `manifest.webmanifest` + service worker + HTTPS-or-localhost criteria are all met).
6. Verify offline behavior for the two navigation routes explicitly whitelisted in `ngsw-config.json`: navigate to `/profile`, then in DevTools → Network set "Offline", then reload / Expect: page still loads from the service-worker cache (no browser offline-dinosaur page). Repeat for `/settings`. Then try a route NOT in `navigationUrls` (e.g. a random unmapped path) while offline / Expect: this is NOT guaranteed to work — confirms the whitelist is actually scoping behavior, not blanket-caching everything.
7. While still offline, check Network tab for any request to `/api/**` made during the above / Expect: per `ngsw-config.json`'s `api-freshness` dataGroup (freshness strategy, 5s timeout), API calls should fail fast / fall through rather than hang, since no API routes exist yet to actually serve cached data — this just confirms the dataGroup config doesn't break anything in the current greenfield state.

**Cleanup:** stop the `http-server` process; in Chrome DevTools → Application → Service Workers, click "Unregister" and Application → Storage → "Clear site data" to remove the installed PWA/service-worker state before testing other local projects on the same port/origin.
