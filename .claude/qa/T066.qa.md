## Manual QA — T066

**Prerequisites:**
- The docker infrastructure plus the user-service, discovery-service and API gateway are running.
- The Angular dev server is running (`cd src/frontend; npm start`, then http://localhost:4200).
- You have two test accounts that completed Profile Setup: one with gender Female, one with gender Male (or Unspecified).
- You have a browser with DevTools available.

1. Log in as the **Male/Unspecified** account at http://localhost:4200 and go to `/radar`.
   Expect: the idle Radar screen with a gear button in the top bar. The button shows a pointer cursor and is no longer disabled.
2. Click the gear button.
   Expect: a bottom sheet slides up (about 0.2s) over a violet-tinted overlay. It shows a handle bar, the title "Discovery Filters", a Radius slider labelled "1.0 km", a segmented control with "±30 min" highlighted, and an "Apply Filters" button.
3. Right-click the sheet, choose Inspect, and search the Elements panel (Ctrl+F) for `women-only` and `Women-only mode`.
   Expect: zero matches. No toggle element, not even hidden.
4. Drag the slider to the far left, then the far right.
   Expect: the readout shows 0.5 km at the left and 5.0 km at the right, moving in 0.5 steps. Set it to 2.5 km.
5. Click "±60 min".
   Expect: it becomes highlighted and "±30 min" is de-highlighted.
6. Press Esc, then click the gear button again.
   Expect: the sheet closes on Esc; on re-open it shows 1.0 km and ±30 min again. The dismissed edits were not saved.
7. Click the gear button, set 2.5 km and ±60 min, click "Apply Filters".
   Expect: the sheet closes. No network request to /discovery/scan/* appears in DevTools Network at this point (apply sends nothing).
8. Click the gear button again.
   Expect: the sheet re-opens showing 2.5 km and ±60 min, the stored values.
9. With DevTools Network open, enter a destination, set a departure time and click Start Scan, allowing location permission.
   Expect: a `POST .../discovery/scan/start` request. Its payload contains `radius_km: 2.5`, `departure_window_minutes: 60` and `women_only: false`, plus the destination fields. The response is 200 (the server ignores the two new fields, a known gap). The radar becomes active.
10. Stop the scan, reload the page (F5), go to `/radar`, click the gear button.
    Expect: the sheet shows the defaults again, 1.0 km and ±30 min, because filter state is in memory only by design (no localStorage).
11. Sign out, log in as the **Female** account, go to `/radar`, click the gear button.
    Expect: the same sheet, plus a "Women-only mode" switch row between the departure window and the Apply button.
12. Inspect the Elements panel, searching for `women-only`. Turn the switch on and click Apply Filters.
    Expect: the switch is present for this user; it moves right and turns violet, and the sheet closes.
13. Start a scan as the Female user.
    Expect: the POST `/discovery/scan/start` payload contains `women_only: true`.
14. Resize the browser to about 400px wide and click the gear button, then resize to 1200px.
    Expect: at 400px the sheet is full width with rounded top corners; at 1200px it is capped at about 430px wide and centered at the bottom.
15. Edge case, lookup failure: block the `/user/users/me` request (DevTools Network, right-click the request, Block request URL) as the Female user and reload `/radar`. Click the gear button.
    Expect: the women-only row is absent (fail closed).

**Cleanup:** Unblock the request in DevTools, stop any active scan with the Stop button, log out, and stop the Angular dev server (Ctrl+C).
