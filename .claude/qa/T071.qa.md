## Manual QA — T071

**Prerequisites:**
- Docker Desktop running.
- Node 20+, installed Angular dependencies in `src/frontend`, and openssl available (it ships with Git Bash).
- At least one real user row in user-service.
  - If none exists, sign in once through the app's Google login to create one.
- The compose and `.env` steps below were not executed by the reviewer, so verify them as you go.
  - There is no compose file at the repo root.
  - The stack lives in `src/infra`, and the repo's `.env` is at the root.
- `JWT__RSAPRIVATEKEYPEM` is blank in the repo's `.env`, so user-service signs with a throwaway key you cannot reach.
- user-service issues `role="user"` only (`JwtIssuer.cs:108`), and the gateway trusts only user-service's JWKS. To get an admin session you must give user-service a known key and sign an admin token yourself.
- The override "not stored" warning needs the Rating client stub still in place (`RatingServiceClientImpl.overrideTrustScore` only logs and echoes). It appears only while that stub exists.
- Throughout, a browser DevTools console on `http://localhost:4200` is used to set tokens.

**Update - real admin sign-in now exists:** user-service issues `role=admin` for ids listed in `ADMIN__USERIDS` (`.env`, passed to the container as `Admin__UserIds`). You can skip hand-minting in steps 1, 2 and 5 for the admin session: sign in through the app once, find your numeric user id (decode your access token's `sub`, or read the Users table), set `ADMIN__USERIDS=<that id>` in `.env`, run `cd src/infra && docker compose --env-file ../../.env up -d --build user-service`, then sign in again (the role is stamped at issuance, so an existing token stays `user`). Expect the new access token's decoded payload to show `"role":"admin"`, and it keeps it after a refresh. Steps 6 onward are unchanged (the non-admin check can use any normal sign-in).

**Steps:**

1. Create a persistent signing key.
   - Open Git Bash in the repo root. Run: `openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out dev-admin-key.pem`
   - Run: `awk 'NF {sub(/\r/,""); printf "%s\\n",$0;}' dev-admin-key.pem`
   - Copy the single-line output.
   Expect: one line starting `-----BEGIN PRIVATE KEY-----\n...`.

2. Put the key in `.env`.
   - Edit `.env` at the repo root.
   - Replace the line `JWT__RSAPRIVATEKEYPEM=` with `JWT__RSAPRIVATEKEYPEM="<the line from step 1>"`, keeping the double quotes so Compose turns `\n` into newlines.
   - Never commit this value.
   Expect: the `.env` line is non-empty.

3. Start the stack.
   - Run: `cd src/infra && docker compose --env-file ../../.env up -d --build`
   - Wait about 2 minutes. Then run: `docker compose --env-file ../../.env ps`
   Expect: `api-gateway`, `user-service`, `admin-service`, `report-service`, `rating-service`, `connection-service`, `sqlserver` and `mongodb` are all running or healthy.
   - Run: `docker logs user-service 2>&1 | grep -i ephemeral`
   Expect: no output. If you see the ephemeral-keypair warning, the PEM did not load; fix the quoting in step 2 and re-run `up -d`.

4. Start the frontend.
   - In a second terminal run: `cd src/frontend && npm start`
   Expect: "Application bundle generation complete" and `http://localhost:4200/` serving. The dev configuration points at `http://localhost:8080`.

5. Mint the admin token.
   - Save the following as `mint-admin.js` in the repo root and run `node mint-admin.js` from the repo root.
   - It needs the user-service JWKS, which is exposed on host port 8081.
   ```
   const fs = require('fs'), crypto = require('crypto');
   (async () => {
     const jwks = await (await fetch('http://localhost:8081/.well-known/jwks.json')).json();
     const kid = jwks.keys[0].kid;
     const b64 = o => Buffer.from(JSON.stringify(o)).toString('base64url');
     const now = Math.floor(Date.now() / 1000);
     const head = b64({ alg: 'RS256', typ: 'JWT', kid });
     const body = b64({ sub: '999999', role: 'admin', gender: 'Unspecified', iss: 'shareconnectsave-platform', aud: 'shareconnectsave-api', iat: now, exp: now + 3600 });
     const sig = crypto.sign('RSA-SHA256', Buffer.from(head + '.' + body), fs.readFileSync('dev-admin-key.pem')).toString('base64url');
     console.log(head + '.' + body + '.' + sig);
   })();
   ```
   Expect: one long `xxx.yyy.zzz` token printed. The token is valid for one hour; mint a new one if it expires.
   - Also mint a non-admin token by changing `role: 'admin'` to `role: 'user'`, saving as `mint-user.js`, and running it.

6. Non-admin is blocked (AC1).
   - Open `http://localhost:4200` in a Chromium browser and open DevTools, Console.
   - Run: `localStorage.setItem('scs_access_token','<non-admin token>')`
   - Navigate to `http://localhost:4200/admin`.
   Expect: a red toast "You do not have access to that page." and a redirect to `/radar`. In DevTools, Network, JS, no admin chunk is downloaded.
   - Also run `localStorage.removeItem('scs_access_token')` and go to `/admin`.
   Expect: redirect to `/auth/login`.

7. Admin reaches the queue.
   - Run: `localStorage.setItem('scs_access_token','<admin token>')`
   - Navigate to `http://localhost:4200/admin`.
   Expect: the review queue page. It lists suspended accounts only, so it may show an empty state. Any degraded rows show a notice, not zeros.

8. Open a user and find a user id.
   - Sign in normally as a regular user in another browser profile, or read an existing id from the database.
   - In that session's console, run: `JSON.parse(atob(localStorage.scs_access_token.split('.')[1])).sub`
   - Back in the admin session, go to `http://localhost:4200/admin/users/<that id>`.
   Expect: Profile, Trust score and Reports cards. If a card says "unavailable", that is the known-broken-upstream notice working, not a UI bug.

9. Suspend updates the UI immediately (AC2).
   - On an Active user, click Suspend. Type a reason and click Suspend in the sheet.
   Expect: the sheet closes, the status chip turns Suspended and the button shows "Suspending…" at once. A green toast "<name> suspended." appears and you are returned to `/admin`, where that user is now listed.

10. Reinstate updates the UI immediately (AC2).
    - Click that user in the queue, then click Reinstate.
    Expect: the chip flips to Active at once and the button shows "Reinstating…". A green toast "<name> reinstated." appears, you return to `/admin`, and the user is gone from the queue.

11. Failure rollback (edge case).
    - Run `docker stop user-service` (this does not stop the gateway or admin-service).
    - On an Active user, try Suspend.
    Expect: the chip briefly shows Suspended, then rolls back to Active. A red toast appears with the server's message, plus a hint where one applies. A silent re-check runs, and its failure toast, if shown, reads "Could not re-check this user's state."
    - Run `docker start user-service`.

12. Override score shows the "not stored" warning (stub in place).
    - On a user detail page where the trust score shows a number, click Override score.
    - Enter a score different from the current one, between 1.0 and 5.0, and a reason, and click Save override.
    Expect: "Saving…" on the button, then a red toast "The override was accepted but not stored: Rating Service does not persist trust-score changes yet." The score on screen goes back to the original value. You should not see "Trust score updated."
    - Edge cases: 0 or 5.1 leaves Save override disabled. An empty reason also leaves it disabled.

13. Stats refresh every 60 s (AC3).
    - Navigate to `http://localhost:4200/admin/stats`.
    - In DevTools, Network, filter on `stats`.
    Expect: one `GET .../admin/admin/stats` on page load, then another at roughly 60 s intervals. The "Last updated" caption counts up each second and resets after each refresh.
    - Stop `report-service` with `docker stop report-service` and wait for the next refresh.
    Expect: the last good numbers stay with an error notice, or a card shows "Unavailable". Polling continues.
    - Run `docker start report-service`.
    - Known quirk: follow-ups.md T103 item 6 says the report-service circuit breaker may trip after about 5 loads and degrade the stats.

14. Logout clears the queue (cycle-1 fix).
    - Visit `/admin` and note the rows.
    - Run `localStorage.clear()` in the console, then set the admin token again and reload `/admin`.
    Expect: a loading state and then fresh data, never the earlier snapshot flashing.

**Cannot be exercised end to end:**
- The override success path (green "Trust score updated.") cannot be seen until the Rating Service really persists scores.
- A real admin sign-in via Google cannot be done, because user-service never issues role `admin`; the hand-minted token is the only path today.

**Cleanup:**
- `localStorage.clear()` in the browser console.
- Stop the frontend with Ctrl+C.
- Run `cd src/infra && docker compose --env-file ../../.env down`.
- Delete `dev-admin-key.pem`, `mint-admin.js` and `mint-user.js` from the repo root.
- Remove the `JWT__RSAPRIVATEKEYPEM` value from `.env`, leaving the line as `JWT__RSAPRIVATEKEYPEM=`.
