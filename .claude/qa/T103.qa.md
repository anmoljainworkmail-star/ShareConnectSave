## Manual QA — T103

**Prerequisites:**
- You run the rebuild yourself (Docker is not run from the main session). From the repo root: `docker compose -f src/infra/docker-compose.yml -f src/infra/docker-compose.override.yml up -d --build report-service admin-service`. Keep mongodb, kafka, user-service and rating-service running.
- Ports: report-service `localhost:8087`, admin-service `localhost:8088`, gateway `localhost:8080`, host Mongo `27018`.
- Use Git Bash or any shell with curl.
- Target user T = `11111111-1111-1111-1111-111111111111`, reporter A = `aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa`, reporter B = `bbbbbbbb-bbbb-bbbb-bbbb-bbbbbbbbbbbb`, user with no reports Z = `99999999-9999-9999-9999-999999999999`.
- The gateway route cannot be exercised here: it needs a real JWT with `role=admin` and no dev admin seed exists. Hit report-service (8087) and admin-service (8088) directly, sending the headers the gateway would inject.
- Escalation threshold is 3 (`REPORT_ESCALATION_THRESHOLD`), so the first two reports stay `open`.

1. Seed two reports against T (older first).
   `curl -s -i -X POST http://localhost:8087/reports -H "Content-Type: application/json" -H "X-User-Id: aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa" -d '{"reported_id":"11111111-1111-1111-1111-111111111111","reason":"Harassment","details":"first"}'`
   Wait 2 seconds, then:
   `curl -s -i -X POST http://localhost:8087/reports -H "Content-Type: application/json" -H "X-User-Id: bbbbbbbb-bbbb-bbbb-bbbb-bbbbbbbbbbbb" -d '{"reported_id":"11111111-1111-1111-1111-111111111111","reason":"Fake profile","details":"second"}'`
   Expect: both `HTTP/1.1 201`; body has `id`, `reporter_id`, `reported_id`, `reason` ("Harassment" then "Fake profile"), `status:"open"`, `created_at`.

2. Happy path, admin, id header omitted (the exact shape admin-service sends).
   `curl -s -i "http://localhost:8087/reports?reportedId=11111111-1111-1111-1111-111111111111" -H "X-User-Role: admin"`
   Expect: `200`, JSON array of 2 objects, newest first. First element has `"details":"second"` and `"reason":"Fake profile"`; second has `"details":"first"`. snake_case fields (`reporter_id`, `reported_id`, `connection_id`, `created_at`). Newest `created_at` is the later one.

3. Happy path with both headers (X-User-Id accepted but optional).
   `curl -s -i "http://localhost:8087/reports?reportedId=11111111-1111-1111-1111-111111111111" -H "X-User-Role: admin" -H "X-User-Id: cccccccc-cccc-cccc-cccc-cccccccccccc"`
   Expect: `200`, same array as step 2.

4. User with zero reports.
   `curl -s -i "http://localhost:8087/reports?reportedId=99999999-9999-9999-9999-999999999999" -H "X-User-Role: admin"`
   Expect: `200`, body exactly `[]`. Must not be 404.

5. Non-admin role.
   `curl -s -i "http://localhost:8087/reports?reportedId=11111111-1111-1111-1111-111111111111" -H "X-User-Role: user" -H "X-User-Id: aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa"`
   Expect: `403`, body `{"code":"ADMIN_ROLE_REQUIRED","message":"User aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa is not authorized to perform this admin-only report action","traceId":""}`.
   Repeat without `X-User-Id`: still `403`; message says `User (no X-User-Id header) is not authorized...`. Must not be 500.

6. Missing `reportedId`.
   `curl -s -i "http://localhost:8087/reports" -H "X-User-Role: admin"`
   Expect: `400`, body `{"code":"MISSING_REQUIRED_INPUT","message":"Required parameter or header 'reportedId' is missing.","traceId":""}`.

7. Missing `X-User-Role`.
   `curl -s -i "http://localhost:8087/reports?reportedId=11111111-1111-1111-1111-111111111111"`
   Expect: `400`, body `{"code":"MISSING_REQUIRED_INPUT","message":"Required parameter or header 'X-User-Role' is missing.","traceId":""}`. Body must not contain any value you sent.

8. Sibling routes did not regress.
   - `curl -s -i http://localhost:8087/reports/queue -H "X-User-Id: aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa" -H "X-User-Role: admin"` -> `200`, JSON array (empty until a third report escalates).
   - `curl -s -i http://localhost:8087/reports/queue -H "X-User-Role: admin"` -> now `400` naming `X-User-Id` (previously 500; documented side effect).
   - `curl -s -i "http://localhost:8087/reports/top-reported?days=7&limit=5" -H "X-User-Role: admin"` -> `200`, `[{"reported_id":"11111111-...","report_count":2}]`.
   - `curl -s -i "http://localhost:8087/reports/top-reported" -H "X-User-Role: user"` -> `403` `ADMIN_ROLE_REQUIRED`.

9. Escalation sanity. File a third report against T from reporter C (`X-User-Id: cccccccc-cccc-cccc-cccc-cccccccccccc`, reason "Other"). Repeat step 2.
   Expect: `200`, 3 reports newest first, all with `"status":"escalated"`.

10. Admin-service now returns populated report history. Needs a real user UUID U that exists in User Service (404 for unknown ids; read one from the Users table or sign in once through the app). File 2 reports against U as in step 1 (`"reported_id":"<U>"`). Then:
    `curl -s -i http://localhost:8088/admin/users/<U> -H "X-User-Role: admin" -H "X-User-Id: dddddddd-dddd-dddd-dddd-dddddddddddd"`
    Expect: `200`, `reportHistoryUnavailable:false`, `reportCount:2`, `reportHistory` with 2 entries (camelCase: `id`, `reporterId`, `reason`, `status`, `createdAt`), newest first.
    Log check: `docker logs admin-service --since 5m | grep "Report Service history unavailable"` must print nothing.
    If you have no real user, record this step as not exercised; step 2 plus the logs show the endpoint works.

11. Dashboard top-reported tile.
    `curl -s -i http://localhost:8088/admin/stats -H "X-User-Role: admin" -H "X-User-Id: dddddddd-dddd-dddd-dddd-dddddddddddd"`
    Expect: `200`, `topReportedUsersUnavailable:false`, `topReportedUsers` containing `{reportedId:"<T or U>", reportCount:N}`. Other tiles may show unavailable if their upstream services are down.
    `totalReportsTodayUnavailable:true` is expected: the known T060 gap (unfiltered `GET /reports` has no endpoint and returns 400).
    Caution: each stats load adds one failure to the shared `reportService` circuit breaker (see follow-up #6 in `.claude/notes/follow-ups.md`). Do not load `/admin/stats` more than about 4 times in a row; otherwise `topReportedUsersUnavailable` and `reportHistoryUnavailable` can flip to true for about 30 seconds even though report-service is healthy. Wait 30 seconds and retry.

**Cleanup:** Remove seeded reports, e.g. `docker exec mongodb mongosh --quiet ReportServiceDb --eval 'db.reports.deleteMany({reportedId:{$in:["11111111-1111-1111-1111-111111111111","<U>"]}})'` (adjust container name if yours differs). Admin-service wrote no data.
