## Manual QA — T105

**Prerequisites:** Docker Desktop running; `.env` populated from `.env.example` (including `INTERNAL_SERVICE_KEY` — defaults to `dev-internal-key-123` if unset); run `docker compose up` from `src/infra` (or `/docker-up`) to bring up SQL Server and user-service. At least one row in `Users` with `AccountStatus = 'Active'` and `IsOnboardingComplete = 1`, and at least one row that is either `AccountStatus = 'Suspended'` or `IsOnboardingComplete = 0`, so the count is provably filtering, not just returning `COUNT(*)` over the whole table.

1. `curl -i http://localhost:<user-service-port>/users/internal/stats -H "X-Internal-Service-Key: dev-internal-key-123"`
   Expect: `200 OK`, body `{"total_active_users": <N>}` where `<N>` matches only the rows that are both not-suspended and onboarding-complete (verify by hand against the seeded rows above).
2. `curl -i http://localhost:<user-service-port>/users/internal/stats` (no header at all)
   Expect: `401 Unauthorized`, body `{"code":"INVALID_INTERNAL_KEY","message":"Internal service authentication failed.","traceId":"<some-guid>"}`.
3. `curl -i http://localhost:<user-service-port>/users/internal/stats -H "X-Internal-Service-Key: wrong-key"`
   Expect: same `401` + same error envelope shape as step 2 (mismatched key is treated identically to missing key).
4. With all rows' `AccountStatus` set to `Suspended` or `IsOnboardingComplete` set to `0` (temporarily, in a scratch/dev DB only): repeat step 1.
   Expect: `200 OK`, body `{"total_active_users": 0}` — not an error, not `null`.
5. From inside the admin-service container/process (or a unit test harness), invoke `UserServiceClient.getStats()` directly and confirm it returns a `PlatformStats(totalActiveUsers=<N>)` matching step 1's number.
6. Stop the user-service container, then invoke `UserServiceClient.getStats()` from admin-service repeatedly (≥10 calls, matching `minimum-number-of-calls: 10` in `application.yml`) until the `userService` circuit breaker trips.
   Expect: calls throw (propagate, no silent zero/placeholder returned) once the breaker is OPEN — confirm via `/actuator/health` on admin-service showing the `userService` circuit breaker component as `OPEN`.

**Cleanup:** Restore any rows you temporarily edited for step 4 back to their original `AccountStatus`/`IsOnboardingComplete` values; restart the user-service container after step 6 to reset the circuit breaker state; `docker compose down` if infra was started solely for this QA pass.
