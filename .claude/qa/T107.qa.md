## Manual QA — T107

**Prerequisites:** connection-service and admin-service running locally (`docker-up` stack + both services started). Have at least one connection accepted today via the normal `/connections/{id}/accept` flow to get a non-zero count.

1. `curl -i -X GET http://localhost:<connection-service-port>/admin/connections/stats -H "X-User-Role: admin"`
   Expect: `200 OK`, body `{"total_connections_accepted_today": <N>}` where N matches the number of connections actually accepted today.

2. `curl -i -X GET http://localhost:<connection-service-port>/admin/connections/stats`
   (no `X-User-Role` header at all)
   Expect: `403 Forbidden`, body `{"code":"ADMIN_ROLE_REQUIRED","message":"Caller is not authorized to view connection stats","traceId":"..."}`.

3. `curl -i -X GET http://localhost:<connection-service-port>/admin/connections/stats -H "X-User-Role: user"`
   Expect: identical `403`/`ADMIN_ROLE_REQUIRED` shape as step 2 — confirms missing-header and wrong-value collapse to the same response.

4. Accept zero new connections today (fresh test env) and repeat step 1.
   Expect: `200 OK`, `{"total_connections_accepted_today": 0}` — not a 404, not a null body.

5. Through admin-service (once wired to a route, or via a quick test harness calling `ConnectionServiceClient.getStats()` directly): confirm it returns the same integer as step 1 and that killing connection-service mid-call causes the circuit breaker to propagate a failure (not a silently fabricated `0`).

**Cleanup:** none required — read-only endpoint, no state created by this QA pass beyond the connection acceptance used as test data.
