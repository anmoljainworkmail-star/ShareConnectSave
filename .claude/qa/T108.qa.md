## Manual QA — T108

**Prerequisites:** report-service running locally (`/docker-up` for Mongo, then the service itself), at least a few `Report` documents in the `reports` collection spanning different `createdAt` timestamps, statuses, and `reportedId` values (file a few via `POST /reports` as different reporters against a couple of target users to get non-trivial counts).

1. `curl -i http://localhost:<report-service-port>/reports/top-reported -H "X-User-Id: u-admin-1"` (no `X-User-Role` header at all)
   Expect: `400 Bad Request` from Spring's own missing-header handling (not this endpoint's 403 path) — consistent with `/reports/queue`'s existing behavior for the same omission.

2. `curl -i http://localhost:<report-service-port>/reports/top-reported -H "X-User-Id: u-123" -H "X-User-Role: user"`
   Expect: `403 Forbidden`, body `{"code":"ADMIN_ROLE_REQUIRED","message":"User u-123 is not authorized to perform this admin-only report action","traceId":"<non-empty-or-empty-string>"}`.

3. `curl -i http://localhost:<report-service-port>/reports/top-reported -H "X-User-Id: u-admin-1" -H "X-User-Role: admin"` (no `days`/`limit` — defaults)
   Expect: `200 OK`, JSON array of up to 5 objects shaped `{"reported_id": "<uuid>", "report_count": <int>}`, sorted descending by `report_count`, reflecting reports from the last 7 days only, across all statuses (open/escalated/etc. all counted).

4. `curl -i "http://localhost:<report-service-port>/reports/top-reported?days=30&limit=2" -H "X-User-Id: u-admin-1" -H "X-User-Role: admin"`
   Expect: `200 OK`, at most 2 entries, reflecting a 30-day window (should include/exceed what query 3 showed if older reports exist).

5. `curl -i "http://localhost:<report-service-port>/reports/top-reported?limit=-1" -H "X-User-Id: u-admin-1" -H "X-User-Role: admin"`
   Expect (documents the known gap — see follow-ups.md "From T108" item 1): currently returns `500 Internal Server Error` rather than a clean `400` — confirms the validation gap; not a release blocker but worth re-running after the follow-up fix lands.

6. Via admin-service: trigger whatever dashboard action calls `ReportServiceClient.getTopReported(7, 5)` and confirm the dashboard tile renders the same `reported_id`/`report_count` pairs as query 3, end-to-end through the circuit-breaker-wrapped client.

**Cleanup:** none required — all requests are read-only; no data was created by this QA pass beyond the seed reports from Prerequisites, which can be left in place or cleared via your normal local Mongo reset.
