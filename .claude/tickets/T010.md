# T010 — Scoop + JDK 21 Install Script

## Why this ticket exists
ShareConnectSave has multiple backend microservices written in Java (Spring Boot) and .NET, plus an Angular frontend and Docker Compose infrastructure. Every contributor's machine must have JDK 21, .NET 9 SDK, Node 20+, and Docker Desktop installed before they can build, test, or run any service locally. Without a one-shot setup script, onboarding is manual, error-prone, and doesn't scale. This ticket automates the entire developer environment setup via Scoop, teaching the principle of infrastructure as code and idempotent operations—key skills when managing distributed systems.

## What to build
- **File:** `/dev-setup.ps1` at project root (PowerShell, no admin required)
- **Installs via Scoop:** `temurin21-jdk`, `intellij-idea-community-edition`
- **Checks/warns:** .NET SDK 9+, Node 20+, Docker
- **Outputs:** Summary of what was installed vs already present
- **Property:** Idempotent—safe to re-run without reinstalling

## Technical specification

Create `/dev-setup.ps1` — a one-shot developer environment setup script for Windows (no admin required):

```powershell
# Installs: Scoop, JDK 21, IntelliJ IDEA Community, .NET 9 SDK check, Node 20, Docker Desktop check
```

Script should:
1. Install Scoop if not present
2. Add `java` and `extras` buckets
3. Install `temurin21-jdk` via Scoop
4. Install `intellij-idea-community-edition` via Scoop
5. Check `dotnet --version` (>= 9) and warn if missing
6. Check `node --version` (>= 20) and warn if missing
7. Check `docker --version` and warn if missing
8. Print a summary of what was installed vs already present

## Acceptance criteria
- [ ] Script runs without admin on Windows 11
- [ ] After running: `java -version` shows 21, `javac -version` shows 21
- [ ] Script is idempotent — re-running doesn't reinstall

## Patterns demonstrated
**Infrastructure as Code (IaC)** — Automated environment provisioning replaces manual steps, enabling self-service onboarding and consistent setups across machines.

**Idempotent Operations** — The script checks for each tool's existence before installing; re-running produces the same result as the first run (no errors, no duplicate installs).

**Guard Clauses** — Early returns and existence checks prevent unnecessary work and cascading errors.

**Cross-Tool Integration** — Script orchestrates one package manager (Scoop) alongside native Windows version checks (`dotnet`, `node`, `docker`) in one coherent flow.

## Agent implementation notes

**Key files to create:**
- `dev-setup.ps1` at project root

**PowerShell specifics:**
- Use `scoop --version` to detect if Scoop is installed; if not, bootstrap via IEX + Scoop's official installer URL
- Use `Get-Command` or `which.exe` (via `where` in PowerShell) to check for `java`, `dotnet`, `node`, `docker`
- Add Scoop buckets with `scoop bucket add java` and `scoop bucket add extras` (safe if already added—Scoop won't error)
- Use `-ErrorAction SilentlyContinue` to suppress warnings for already-installed packages
- Parse version strings: `java -version 2>&1 | Select-String "21"` for JDK validation
- Use `Write-Host` with `-ForegroundColor` for readable output (green for success, yellow for warnings, red for errors)

**Idempotency approach:**
- Before each install, check with `Get-Command` or direct version check
- If already present and correct version, skip the install step and note "Already installed"
- If version mismatch (e.g., Node 19 instead of 20), warn but don't force upgrade—let user decide

**What NOT to do:**
- Do not use `sudo` or require admin privileges
- Do not hardcode paths—rely on PATH environment variable
- Do not leave the script mid-run if a tool is missing; warn and continue
- Do not assume Scoop's default install location; query `(scoop which java)` or parse from `scoop info`

**Testing guidance for reviewer:**
- Run on fresh Windows 11 VM or clean dev machine
- Verify `java -version` and `javac -version` both show 21 after script completes
- Run script a second time; confirm no reinstalls happen and output shows "Already installed"
- Check that warnings (for missing .NET/Node/Docker) are informative but don't block execution
