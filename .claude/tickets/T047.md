# T047 — FCM Setup

## Why this ticket exists
Right now the platform has no way to reach a user who isn't actively looking at the app. SignalR only works while the PWA is open in a browser tab; the moment someone closes it or their phone screen locks, they stop hearing about anything — including a brand-new connection request from a nearby traveler, which by design expires after 10 minutes with no response. Without this ticket, every background notification silently disappears, the fan-out layer in Phase 8 has no push channel to fan out to, and later tickets (connection.requested and connection.accepted push alerts) have nothing to build on. This ticket lays the plumbing only: get Firebase wired up and able to send one notification to one device. The event-triggered pushes come later.

## What to build
- NuGet package: `FirebaseAdmin`
- Config key: `FCM_CREDENTIALS_JSON` (read via `process.env`-style configuration binding — i.e. `builder.Configuration["FCM_CREDENTIALS_JSON"]`, consistent with T035/T036 — path to the Firebase service account JSON file — never hardcode the path or embed the JSON contents)
- Interface: `IFcmNotificationService`
  - Method: `Task SendAsync(string userId, string title, string body, IDictionary<string, string> data)`
- Implementation: `FcmNotificationService` — initializes/holds the Firebase app, looks up the target user's FCM device token, then sends via the Firebase Admin SDK
- A small HTTP client abstraction (e.g. `IUserServiceClient`) for the outbound call to User Service to fetch the device token — do not call `HttpClient` directly from `FcmNotificationService`
- Firebase app initialization in `Program.cs` composition root (single shared instance for the service's lifetime)
- Register `IFcmNotificationService` and its HTTP client dependency in DI

## Technical specification
Integrate Firebase Admin SDK (`FirebaseAdmin` NuGet). Config: `FCM_CREDENTIALS_JSON` via `IConfiguration` (path to service account JSON).

`IFcmNotificationService` with `SendAsync(userId, title, body, data)` — looks up user's FCM device token (stored in User Service, fetched via HTTP).

## Acceptance criteria
- [ ] Service starts and Firebase app initialised
- [ ] `SendAsync` with a real FCM token delivers a notification (smoke test in dev)

## Patterns demonstrated
- **Dependency Inversion** — `FcmNotificationService` depends on `IUserServiceClient` (an abstraction) to fetch the device token, not a concrete `HttpClient` call, and callers elsewhere in the service will depend on `IFcmNotificationService`, not the concrete Firebase SDK type.
- **Singleton (via DI container)** — the Firebase `FirebaseApp` instance is expensive to construct and safe to share; register it once via `AddSingleton` in `Program.cs` rather than re-initializing per request.
- **Single Responsibility** — `FcmNotificationService` only sends pushes; it does not own Kafka consumption, SignalR fan-out, or business rules about *when* to notify (those arrive in later tickets).

- Confirm the actual notification-service folder name and existing `Program.cs` state under `src/services/notification-service` before creating files — T001 only scaffolded the folder structure, so this may be the first real code in the service.
- For the User Service HTTP call: this agent has access to the real User Service code — inspect it to find the actual endpoint that exposes the user's FCM device token field, and call that. Do not guess or invent a path; confirm it from the User Service controller/DTOs.
- Use MVC Controllers style per the `dotnet-mvc-controllers` skill (no Minimal API) — this applies to any controller surface added here, even though this ticket is primarily a service/SDK integration with no new public endpoint required.
- Read `FCM_CREDENTIALS_JSON` through `IConfiguration` (`builder.Configuration["FCM_CREDENTIALS_JSON"]`, the `process.env.*`-for-config preference applied in .NET terms, per T035/T036 precedent), never a hardcoded file path.
- What NOT to do:
  - Do not call Kafka or SignalR from this ticket — that's Phase 8's later tickets (connection.requested / connection.accepted consumers).
  - Do not hardcode a device token, user id, or credentials path for the smoke test — use config/environment and a real test account's token.
  - Do not call `FirebaseMessaging`/`HttpClient` directly from controllers or other services — go through `IFcmNotificationService`.
  - Do not write unit tests for this ticket (per the no-piecemeal-test-retrofits convention — all testing is deferred to the dedicated testing tickets).
