# T062 — Angular PWA Setup

## Why this ticket exists
Travelers using ShareConnectSave are, by definition, on the move — in a train station, a bus terminal, an airport with patchy wifi — exactly where a normal web app breaks the moment connectivity drops. Without this ticket, the app has no service worker, no installable manifest, and no offline caching strategy: closing the browser tab loses your place, a dead zone shows a blank error screen instead of your profile, and there's no way to add the app to an Android home screen like a real app. This ticket turns the Angular app into a Progressive Web App — it installs like a native app, keeps static screens like Profile and Settings usable when offline, and sets the caching rules that every later screen (radar, discovery, chat) will depend on.

## What to build
- `ng add @angular/pwa` run against the existing `src/frontend` project — adds the service worker package, icon set, and `manifest.webmanifest`
- `src/frontend/ngsw-config.json` — configured with:
  - A `dataGroups` entry using strategy `freshness` (network-first) for API calls
  - An `assetGroups` entry using strategy `performance` (cache-first) for static assets
  - `/profile` and `/settings` included as pre-cached static routes
- `src/frontend/src/environments/environment.ts` — all API base URLs sourced via `process.env.*` (Angular env replacement), not hardcoded

## Technical specification
`ng add @angular/pwa` — adds service worker, `manifest.webmanifest`, icons.

Configure `ngsw-config.json`:
- Cache strategy `freshness` for API calls (network-first)
- Cache strategy `performance` for assets (cache-first)
- Static routes (`/profile`, `/settings`) pre-cached

`environments/environment.ts` — all API URLs via `process.env.*` (Angular env replacement).

## Acceptance criteria
- [ ] `ng build --configuration production` succeeds
- [ ] Lighthouse PWA score ≥ 90
- [ ] App installable on Android Chrome

## Patterns demonstrated
- **Cache-Aside (adapted to client-side)** — the `freshness` (network-first) strategy for API data teaches the same underlying idea as server-side cache-aside: try the live source first, fall back to the cached copy only when the live source is unavailable.
- **Performance via immutability** — the `performance` (cache-first) strategy for static assets teaches that content which rarely changes (JS bundles, icons, fonts) should be served instantly from cache rather than re-fetched, trading a small staleness risk for speed.
- **Progressive Enhancement** — the app remains usable (static screens load) when a core capability (network) is unavailable, rather than failing outright.
- **Configuration over hardcoding** — `process.env.*`-driven environment files mean API URLs change per deployment without touching source code.

## Agent implementation notes
- Key files to create/modify (relative to project root):
  - `src/frontend/ngsw-config.json` (created by `ng add @angular/pwa`, then hand-edited for the strategies above)
  - `src/frontend/src/environments/environment.ts` and `environment.prod.ts` — API URLs via `process.env.*`
  - `src/frontend/src/manifest.webmanifest` (generated — verify installability fields: `name`, `short_name`, `icons`, `start_url`, `display`)
  - `src/frontend/src/app/app.module.ts` — `ServiceWorkerModule.register(...)` registration (added automatically by `ng add @angular/pwa`; verify it is gated to production builds)
- This ticket is infrastructure setup with no screen UI — the angular-pwa skill's Visual reference section (FIGMA_SPEC.md and the two approved mockups) does not apply here.
- Do not scaffold any components, modules, or routes beyond what `ng add @angular/pwa` generates — `/profile` and `/settings` routes are referenced only inside `ngsw-config.json`'s `navigationUrls`/asset pre-caching config, not created here.
- Do not introduce standalone components — this project is module-based only (see CLAUDE.md Angular Rules). Anything `ng add @angular/pwa` scaffolds must stay consistent with NgModule style.
- Do not hardcode any API origin/hostname in `environment.ts` — every URL must resolve through `process.env.*` at build time via Angular's environment file replacement, never a literal string.
- Common mistake to avoid: applying `freshness` (network-first) to static assets or `performance` (cache-first) to API calls — this is backwards and will serve stale data or slow down static content. Keep the two strategies scoped exactly as specified.
- Common mistake to avoid: forgetting to register `ServiceWorkerModule` with `enabled: !isDevMode()` (or equivalent) — the service worker must not interfere with `ng serve` during local development.
