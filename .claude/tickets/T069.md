# T069 — Rating Flow

## Why this ticket exists
Rating is the only signal the platform has about whether a meetup actually went well, and that signal is what keeps the whole discovery pool trustworthy — it drives the Trusted badge, throttles request-sending for users who keep getting flagged, and queues genuinely bad actors for suspension. If this screen lets someone submit a rating with no tags selected, or silently skips rating on the Met Successfully path, the trust score becomes noise instead of signal, and the "once both users mark Met Successfully, the platform's involvement ends" boundary (per CLAUDE.md's Responsibility boundary) loses its last meaningful checkpoint before handoff.

## What to build
- `RatingComponent` — shown after chat closes
- Shows the other user's name and photo, fetched via the same authenticated-photo-fetch helper built for `UserCardComponent` (T064) — not a bare `<img src>`
- Tag grid, multi-select:
  - Positive tags (rendered green): Friendly, Respectful, On time, Good communication, Would travel again
  - Negative tags (rendered red): Didn't show up, Fake destination, Abusive, Spam, Asked for money
- Submit button → `POST /ratings`
- "Skip" button, shown only on the timeout path
- On Met Successfully path: submit disabled until at least one tag is selected
- On successful submit (or Skip, on timeout path) → navigate to home/radar

## Technical specification
`RatingComponent` — shown after chat closes.
- Shows the other user's name and photo (same authenticated-fetch requirement as `UserCardComponent`, REQUIREMENTS.md §2 — not a bare `<img src>`)
- Tag grid (positive tags green, negative tags red)
- Multi-select (can pick multiple tags)
- Submit button → calls `POST /ratings`
- On timeout path: "Skip" button available

## Acceptance criteria
- [ ] At least one tag required on Met Successfully path (submit disabled otherwise)
- [ ] Skip available on timeout path
- [ ] After submit → navigate to home/radar
- [ ] Other user's photo is fetched with an authenticated request and still renders correctly

## Patterns demonstrated
- **Single Responsibility (S)** — `RatingComponent` owns only displaying the other user's info and collecting/submitting tags; it does not own trust-score calculation, which stays server-side in Rating Service's `TrustScoreCalculator`.
- **Don't Repeat Yourself, via a shared authenticated-fetch helper** — reuses the same photo-fetch-to-blob-URL helper built for `UserCardComponent` (T064) rather than a second implementation, keeping the REQUIREMENTS.md §2 photo-auth rule correct in exactly one place.
- **Open/Closed (O)** — the positive/negative tag lists are rendered from a fixed config list, not hardcoded branching logic, so a future new tag is a config addition rather than a change to the submit-validation code.

## Agent implementation notes
- Key files to create (paths from project root):
  - `src/frontend/src/app/features/rating/rating.module.ts` — `RatingModule`, declares `RatingComponent`, lazy-loaded
  - `src/frontend/src/app/features/rating/rating.component.ts` (+ `.html`, `.css`) — tag grid, multi-select state, submit/skip logic
- Reuse the authenticated-photo-fetch helper already built for `UserCardComponent` (T064) — do not reimplement the authenticated-fetch-to-blob-URL logic a second time.
- Positive and negative tag lists must come from a single config/constant list (not inline conditional branches) so each tag's color (green/red) is derived from which list it belongs to.
- Multi-select state should track selected tags as a set/array bound to the grid, with the Submit button's disabled state derived directly from "is this array empty" on the Met Successfully path.
- Distinguish the two entry paths (Met Successfully vs. timeout) via route data or navigation state passed from `ChatComponent` (T068) — the Skip button must only render on the timeout path.

**What NOT to do:**
- Do not use a bare `<img src="{{photo_url}}">` for the other user's photo — fetch it via the same authenticated helper used by `UserCardComponent` and bind the resulting blob URL.
- Do not allow Submit to be enabled with zero tags selected on the Met Successfully path.
- Do not show the Skip button on the Met Successfully path — it is timeout-path only.
- Do not build `RatingComponent` as a standalone component — this project is module-based only, no exceptions.
- Do not hardcode tag-to-color logic as a chain of `if/else` per tag name — derive color from list membership so adding a tag later is a config change, not a code change.
