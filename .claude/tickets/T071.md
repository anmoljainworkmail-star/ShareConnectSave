# T071 — Admin Dashboard UI

## Why this ticket exists
Admins need a single screen to see flagged accounts, drill into a user's profile/trust score/report history, and suspend or reinstate them — without that, every moderation action is a manual backend call with no visibility into whether it worked. This ticket is explicitly **not** ready to start just because T057, T059, and T060 show `[x]` in PROGRESS.md: T057 is marked done even though its User Service and Report Service calls are currently broken (see Phase 16), and that breakage has been invisible so far because nothing renders it — this UI's "User detail" and "Queue list" pages are the first place it becomes visible on screen (nulled-out profile fields, an empty suspended-accounts queue, a report-history section that never loads) instead of just an exception in a server log. Do not start this ticket until **both T102 and T103** show `[x]` in PROGRESS.md, even if T057/T059/T060 are already done.

## What to build
- `AdminModule` — lazy loaded via `loadChildren`, module-based (no standalone components)
- `AdminGuard` — route guard that checks the `X-User-Role` claim in the JWT; blocks non-admin access
- Queue list page — flagged accounts
- User detail page — profile + trust score + reports
- Stats dashboard page — consumes T060 data

## Acceptance criteria
- [ ] Non-admin JWT → cannot access admin routes
- [ ] Suspend and reinstate actions update UI immediately
- [ ] Stats dashboard refreshes every 60 s

## Patterns demonstrated
- Guard pattern — `AdminGuard` centralizes the route-access check (role claim) in one place instead of every admin page re-checking it.
- Facade/aggregation — the pages consume already-aggregated admin-service endpoints (T057/T059) rather than calling User/Report/Rating services directly from the frontend.
- Lazy loading — `AdminModule` is loaded only when an admin navigates to it, keeping it out of the main bundle for regular users.
- Optimistic/immediate UI update — suspend/reinstate actions reflect in the UI right away rather than waiting for a full page reload.
- Polling — the stats dashboard re-fetches on a fixed interval (60 s) rather than requiring a manual refresh.
