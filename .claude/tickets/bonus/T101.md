# T101 — Where ngrok Actually Sits (Request Path Write-Up)

## Why this ticket exists
T097–T100 all tune your own servers' connector behavior — but it's easy to walk away from that
work thinking ngrok is somehow part of that same layer, or that tuning Tomcat/Kestrel also buys
you control over the tunnel itself. It doesn't, and conflating the two is exactly the kind of
"looks right, isn't" gap this project's README keeps finding in real infrastructure — this time
in a mental model instead of a config file. This ticket exists purely to write that distinction
down clearly, once, so it never has to be re-derived.

## What to build
A single markdown file, `docs/request-path.md`, containing a labeled diagram (ASCII art or a
Mermaid flowchart) tracing one real request end to end:

```
client → ngrok edge (TLS terminates HERE) → plain HTTP tunnel → your machine
       → api-gateway's Kestrel connector (T098's limits apply here)
       → YARP forwards the request
       → downstream service's own connector — Tomcat for Java, Kestrel for .NET
         (T097's limits apply here)
       → controller / filter chain code
```

Alongside the diagram, plain-English prose (same "explain it like I've never heard of it, real
analogy first" convention this project's other teaching material already uses) covering:
- Where TLS actually terminates (at ngrok's edge) and why that matters: ngrok sees your request
  as HTTPS from the client's side, but your own local services never see TLS at all — the tunnel
  itself carries plain HTTP from ngrok to your machine.
- What ngrok's free tier does **not** give you control over: connection backlog, concurrent
  connection limits, request queuing behavior — all the things T097 and T098 just gave you
  control over, but only for your own processes, never for the tunnel in front of them.
- Why a real production deployment would put a real load balancer (an ALB, nginx, Cloudflare) in
  ngrok's position instead, and what that load balancer would additionally give you that ngrok
  structurally can't.

## Technical specification
No code. One diagram, one page of explanatory prose, reviewed for accuracy rather than tested at
runtime.
