Map background options, side by side

Same rings, sweep and standing figures in all three — only the backdrop changes. Option 2 is the classic green-land/blue-ocean atlas look: no real coastline, no real location, just that visual language. Neither option claims to show anyone's actual street or coastline — distance rings still mean real distance; figure position is still spread for legibility, not real bearing, same as today.

What would actually change

  • Background only, either option — a new layer behind the rings. Rings, sweep, "Me", and the standing figures are untouched in both.
  • Option 1 stays inside the violet token scale — street-grid lines + muted blocks, all existing violet tokens, zero new colors.
  • Option 2 steps outside it, on purpose — a real atlas needs its own green/blue; both are muted and a dark vignette sits under the rings so the violet UI chrome still reads clearly on top. Worth deciding deliberately, the same way the earlier avatar-gender question was, not drifting into it as "just a background."
  • Option 2's extra atlas cues — elevation-shaded terrain (green lowland fading to olive/brown highland, not a flat green), a lighter shallow-water halo around each coastline, small mountain-range glyphs, a compass rose, and decorative lat/long tick labels at the margins.
  • Option 2's "feels current" pass — a small blurred aurora/iridescent glow (the same accent Spotify/Threads-style apps use) and the sticker/emoji visual language apps like BeReal and Partiful use, rather than a strictly academic atlas read.
  • Fixed: the plane now actually flies — the previous version rode an SVG `animateMotion` path that looked exact on paper but didn't reliably animate here (it sat frozen). Swapped to the same plain CSS `@keyframes` mechanism the boat has used successfully the whole time; it's an approximation of the curve rather than a mathematically exact path-lock, but it actually moves.
  • Dashed line now connects dead center to dead center — two rounds of "near the edge" estimates both still read as not quite reaching the green, so this goes all the way to each landmass's own geometric center instead, removing any ambiguity about which landmass it's attached to.
  • Plane now flies the actual drawn line — the previous version's 5 hand-picked waypoints were a loose enough approximation that the plane visibly drifted off the dashes between them. Re-sampled the identical quadratic curve at 11 points using the real bezier formula (not eyeballed), so the plane's path and the dashed line's path are now mathematically the same curve, not two similar-looking ones.
  • Car is a real red car — swapped the hand-drawn car shape (which wasn't reading as a car) for the 🚗 emoji, already a recognizable red sedan in essentially every font, looping the bottom-left landmass's inner contour ring via the same reliable CSS-keyframe approach.
  • Boat: bottom-left to top-right, blue only — threads the one open-water gap between the two landmasses the whole way, checked against both landmasses' bounding boxes and the bottom card's own footprint so it never crosses into a landmass.
  • Neither is geo-accurate — generic repeating pattern or generic continent blobs, not your real streets or coastline.
  • Low implementation cost either way — pure CSS, no map library, no API key, no extra network request.
